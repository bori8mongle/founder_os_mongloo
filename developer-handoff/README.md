# Pebbling 속마음 앱 개발 인계

## 개발자님께 먼저 드리는 안내

안녕하세요. 이번 작업은 Prompt Lab을 고치는 작업이 아니라, **실제 앱에서
돌멩이 속마음이 생성·검사·저장·표시되는 과정**을 바꾸는 작업입니다.

> **한 문장 요약:** 사용할 수 있는 속마음을 불필요하게 버리지 않으면서,
> 문제가 생긴 결과는 원인을 다시 확인하고 개선할 수 있게 만드는 작업입니다.

### 왜 이 작업을 하나요?

현재는 AI가 속마음을 만든 뒤 별도 Moderation API로 출력만 검사합니다.
`flagged`가 표시되면 답변을 다시 만들거나 최종 실패로 종료할 수 있어,
실제로는 사용해도 되는 답변이 숨겨질 가능성이 있습니다.

또한 지금은 생성·검수에 실패한 결과 원문이 남지 않아, 나중에 “어떤 답변이
왜 실패했는지”를 재현하고 프롬프트나 검사 로직을 개선하기 어렵습니다.

그래서 이번에는 Moderation을 **즉시 차단 기준**보다 **기록하고 개선하기
위한 관찰 신호**로 사용하고, 실제 출력 형식에 문제가 있을 때만 필요한
범위에서 교정하려고 합니다.

### 이번에 바뀌는 핵심

1. **출력 범위를 바꿉니다.**
   - 말풍선 `2~10개`, 개별 최대 `200자`, 전체 최대 `1,000자`
   - 질문 개수는 더 이상 생성 실패 조건으로 사용하지 않고 통계만 남깁니다.

2. **Moderation을 생성 요청 안에서 처리합니다.**
   - 별도 `/v1/moderations` 호출을 없애고, Responses 요청에서 입력·출력
     Moderation 결과를 함께 받습니다.
   - `flagged=true`나 Moderation `type=error`만으로 유효한 속마음을
     숨기거나 다시 생성하지 않습니다. 결과는 표시하고 상태를 저장합니다.

3. **재생성은 형식 교정에만 최대 한 번 사용합니다.**
   - JSON·필드 타입·말풍선 개수·길이가 틀렸을 때만 직전 후보를 교정합니다.
   - 모델 호출은 `최초 1회 + 교정 최대 1회`입니다.
   - timeout 같은 기존 기술 재시도는 그대로 유지합니다.

4. **문제 후보를 서버 전용 진단 기록으로 남깁니다.**
   - 최초·교정 후보, 실패 단계·코드, Moderation 결과를 저장합니다.
   - 앱 사용자는 직접 조회할 수 없고 서버만 접근합니다.
   - 저장하는 모든 후보는 exact match 식별정보 3종을 치환하며, 원문을 콘솔·Sentry/Firebase·
     Google Sheets에 남기지 않습니다.

5. **정상 안전 결과와 최종 생성 실패를 구분합니다.**
   - `THOUGHT_WITH_SAFETY_SUPPORT`는 실패가 아니라, 말풍선과 고정 안전
     도움을 함께 보여주는 정상 결과입니다.
   - 안전 도움 문구·연락처는 AI가 만들지 않고 서버의 승인된 자원을
     사용합니다.
   - 교정까지 실패한 최종 생성 실패는 현재의 일반 실패 화면을
     그대로 사용하고 횟수를 차감하지 않습니다.

위 내용은 모두 **이번에 구현할 목표**입니다. 현재 코드에 이미 모두
반영되어 있다는 뜻이 아닙니다.

## 개발자님이 읽을 문서

현재 구현 기준은 `dev@44bc01c4a7b75f16e867c8848a90b33c1405ecbe`다.

아래 두 문서를 이번 구현 기준으로 함께 읽는다.

1. [속마음 앱 런타임 변경 요청](속마음-출력계약-Moderation-저장-변경요청.md)
2. [속마음 PII 최소 치환 지시서](속마음-PII-결정적-검사-마스킹-상세기획.md)

두 문서는 다음을 정의한다.

- 두 결과 유형 공통 `2~10개 / 개별 200자 / 전체 1,000자`
- 질문 개수 런타임 제한 제거
- Responses inline input/output Moderation
- flagged·Moderation error 상태여도 유효한 속마음은 표시하고 상세 결과는 기록
- 실패·flagged 후보와 검사 결과의 서버 전용 저장
- 구조·개수·길이 오류에 한정한 교정 생성 최대 1회
- 입력과 출력에 똑같이 반복된 PII 3종의 문자열 치환
- 치환 전 식별정보의 생성 결과·진단 후보·일반 로그 저장 방지
- 정상 안전 결과의 `속마음 + 고정 안전 도움` 표시
- 새 DB migration과 v060 finalize
- 앱·서버 수용 테스트와 UI QA

## 이번 작업에서 제외

개발자님은 다음을 수정하지 않는다.

- `tools/prompt-lab/**`
- Google Sheets의 TestCases·Runs·AnswerHistory·결과 시트
- 평가 AI와 평가 프롬프트
- Prompt Lab UI·실행 로직·테스트
- 운영 프롬프트 본문·few-shot·문체
- 테스트 케이스 CSV
- Prompt Lab용 Supabase 테이블
- 실패 후보의 보관 기간·자동 삭제 정책

Prompt Lab은 제품 책임자가 별도 비공개 저장소에서 테스트·비교 전용으로 관리한다.
확정된 운영 프롬프트는 이후 별도 패키지로 전달한다.

## 개발 시작 전 첫 회신

코드를 수정하기 전에 다음만 먼저 알려준다.

1. 현재 작업 브랜치와 기준 커밋
2. ACTIVE 문서 기준 current → changed 요약
3. 예상 변경 파일
4. 새 migration과 RPC 이름
5. 모호하거나 구현을 막는 항목

문서에 확정되지 않은 프롬프트 내용이나 UI를 임의로 추가하지 않는다.
