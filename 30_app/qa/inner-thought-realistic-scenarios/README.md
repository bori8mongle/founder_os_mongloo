# 속마음 실사용 시나리오 제작

## 현재 상태

- 단계: 제작 계획 완료 — 원본 확보 전
- 이번 단계 산출물: 출처 원장과 60개 커버리지 계획
- 아직 하지 않는 일: 시나리오 본문 생성, 실제 모델 실행, Prompt Lab 코드 수정
- 다음 선행조건: 사용할 AI Hub 원본의 다운로드 화면에서 데이터셋별 이용조건·재배포 제한 최종 확인
- 작업 실행계획: [속마음 실사용·장문 시나리오 확장](../../../docs/superpowers/plans/2026-07-28-inner-thought-realistic-scenario-expansion.md)

## 제작 목적

현재 240개 단문 중심 평가 시나리오를 대체하지 않고, 다음 사용 조건을 별도로
검증한다.

- Z세대가 실제로 남길 법한 80자 이상의 생활 기록
- 같은 사건을 여러 번 나누어 쓰는 기록
- 앞 기록을 정정하거나 결과를 덧붙이는 기록
- 긍정·부정·중립 사건이 한 세션에 섞인 기록
- 30분·1시간 동안 여러 번 작성한 기록
- 79·80·81자 생성 자격 경계
- 최근 기록 원문 20,000자 선택·제외·부분 절단

## 결과물 구분

| 결과물 | 개수 | 검증 대상 | 최종 위치 |
|---|---:|---|---|
| 모델 평가 시나리오 | 40 | 장면 선택·근거·말투·안전·재열람 가치 | `developer-handoff/validation/evaluation_scenario_bank.csv` |
| 서버 입력 fixture | 20 | 80자·스냅샷·20,000자·포함/제외 기록 | Prompt Lab 서버 자동 테스트 |

두 결과를 하나의 점수로 합치지 않는다. 모델 문장이 좋아도 입력 기록을 잘못
선택하면 서버 실패이며, 입력 선택이 맞아도 근거 없는 해석이 나오면 모델 품질
실패다.

`19,999~20,001자` 및 그 이상의 항목은 실제 사용자의 대표적인 작성량을
재현하려는 사례가 아니다. 서버가 입력 상한에서 기록을 정확히 선택·절단하는지
검증하는 `input limit fixture`로만 사용한다.

## 제작 순서

1. [출처 원장](source-registry.md)의 이용 조건과 사용 범위를 확인한다.
2. [커버리지 매트릭스](coverage-matrix.csv)의 60개 조합을 검토한다.
3. 원본에서 사건 골격·시간 흐름·말투 특성만 추출한다.
4. 직접 식별정보와 희귀 사건을 제거해 합성 기록으로 다시 작성한다.
5. 모델 평가 40개와 서버 fixture 20개를 서로 다른 형식으로 작성한다.
6. 현실성·제품 계약·개인정보의 3단계 검수를 통과한 항목만 `reviewed`로 바꾼다.
7. 검수 완료본만 developer-handoff와 Prompt Lab으로 승격한다.

## 한 시나리오를 만드는 방법

### 1. 사건 골격

다음 사실만 먼저 작성한다.

- 사용자가 직접 겪은 사건
- 사용자가 직접 표현한 느낌
- 사건의 정정·결과·후속 변화
- 기록 조각 사이의 관계
- 모델이 새로 만들어서는 안 되는 사실

### 2. 페블링 기록으로 변환

- 대화 상대의 발화는 제거한다.
- 사용자 한 명이 시간차를 두고 남긴 기록으로 바꾼다.
- 원문 문장을 그대로 이어 붙이지 않는다.
- 오타·이모지·줄임말은 출처에서 관찰된 수준만 일부 반영한다.
- 30분·1시간 사례는 단일 장문이 아니라 시각이 있는 기록 묶음으로 만든다.

### 3. 기대값

완성된 속마음 문장을 정답으로 쓰지 않고 다음을 고정한다.

- 반드시 알아차려야 하는 사실
- 같은 장면으로 묶어야 하는 기록
- 별도 장면으로 분리해야 하는 기록
- 반영해야 하는 정정·후속 결과
- 금지할 추론·조언·질문
- 일반 속마음 또는 속마음+안전 도움

## 원본·개인정보 규칙

- AI Hub 압축 파일·음성·전사 원문은 Git에 넣지 않는다.
- 원본 권장 보관 위치는 `김세인 개인 Drive/Restricted/Pebbling-AI-Evaluation/AI-Hub`다.
- Founder OS에는 공식 링크·데이터셋 번호·버전·변형 이력만 기록한다.
- 외주개발자에게는 검수된 비식별 합성 시나리오만 전달한다.
- 실제 사용자 기록은 별도 동의·보유 기간·접근 권한이 확정되기 전에는 사용하지 않는다.
- 모델 실행 결과 시트에도 실제 사용자 원문과 AI Hub 원문을 복사하지 않는다.

## 검수 상태

| 상태 | 의미 |
|---|---|
| `planned` | 길이·주제·출처·검증 목적만 확정 |
| `draft` | 합성 입력과 기대값 작성 완료 |
| `reviewed` | 현실성·제품 계약·개인정보 검수 완료 |
| `approved` | 실제 모델 결과까지 제품 책임자가 승인 |
| `retired` | 중복 또는 제품 계약 변경으로 활성 회귀에서 제외 |

원장과 검수 이력은 근거 추적을 위해 보존하되, 초안과 작업 실행계획은 완료 후
