# 페블링 첫 유료상품 출시 작업 맥락

## 1. 이 문서의 역할

이 문서는 첫 유료상품 출시 과정에서 **왜 이 일을 하는지, 어떤 순서로 무엇을
결정·검증해야 하는지, 무엇이 끝나야 출시할 수 있는지**를 잃지 않기 위한 작업
지도다.

아래처럼 자주 바뀌는 값은 이 문서에 복제하지 않는다.

- 현재 앱·브랜치·빌드 버전과 배포 상태
- 세부 개발 진척률과 담당자별 일정
- 최종 가격·할인율·스토어 심사 상태
- 실제 AI 모델명과 단가
- 운영 중 측정되는 전환율·사용량·비용

현재 사실·결정·일정은 [페블링 제품 컨텍스트](../product-context.md), 코드와
기획의 차이는 [개발·기획 차이](02-development-and-planning-gap.md), 데이터·법적
출시 게이트는 [이용약관·개인정보 기준선](03-legal-privacy-baseline.md)을
단일 원본으로 확인한다.

## 2. 변하지 않는 작업 목적

첫 유료상품의 목적은 기능을 많이 추가하는 것이 아니라 다음 두 가지를 검증하는
것이다.

1. 사용자가 페블링이 쌓인 기록을 개인화된 의미로 돌려주는 경험에 실제로
   결제하거나 체험을 시작하는가.
2. 그 경험이 일회성 호기심을 넘어 기록·재열람·주간 재방문을 만드는가.

따라서 기능 수보다 **구매 이유의 명확성, 반복 가치, 측정 가능성**을 우선한다.
마케팅 실행은 별도 작업으로 다루되, 제품 안에는 체험·결제·D7을 판별할 수 있는
측정 기반을 반드시 포함한다.

## 3. 작업의 고정 전제

- 무료 사용자도 기록과 기본 마음돌봄의 핵심 루프를 완성할 수 있어야 한다.
- 첫 유료 가치는 축적된 기록의 개인화된 해석·연결·재발견에서 만든다.
- `돌멩이의 속마음`은 무료에서도 경험하게 하고 유료는 사용량을 확장한다.
- 주간 리포트는 돌탑만의 결과가 아니라, 사용자가 분석에 동의한 여러 기록을
  가로지르는 `알아가기`의 독립 결과물이다.
- AI의 관찰·해석과 사용자가 직접 남긴 원문을 구분한다.
- 자기이해는 AI가 자동 확정하지 않고, 사용자가 확인·수정한 뒤 수첩에 저장한다.
- 기존 3,900원 구매자는 새 구독자와 같은 평생 기능 권한을 받는다.
- 구독이 끝나도 사용자가 만든 원본과 이미 생성된 결과는 계속 열람할 수 있다.
- 사용자 원본과 제품에 보여줄 AI 결과는 저장하되, AI 요청용 원문 사본·숨은
  장기기억·임베딩을 v1에서 별도 축적하거나 범용 모델 학습에 사용하지 않는다.

## 4. 전체 작업 흐름

```text
무료 AI 기반 계약
→ 주간 리포트 v1 계약
→ 무료·체험·유료·기존 구매자 권한 계약
→ 상품 묶음·체험·페이월 계약
→ 개발 추정과 범위 축소
→ 구현 인계
→ 정책·안전·결제·데이터 QA
→ 출시
→ 체험·결제·D7 검증
```

앞 단계의 결과가 뒤 단계의 입력이 된다. 특히 AI의 동의·입력·삭제·안전 계약을
확정하지 않은 채 주간 리포트 구현으로 넘어가지 않는다.

## 5. 작업 묶음과 완료 조건

### A. 무료 AI 기반 계약

목적은 `돌멩이의 속마음`과 이후 주간 리포트가 함께 사용할 안전한 AI 기반을
확정하는 것이다.

해야 할 일:

- 어떤 기록을 어떤 시점에 AI에 보내는지 확정
- AI 기능 진입 안내·동의·철회 흐름 확정
- 원본, AI 결과, 최소 메타데이터, 로그의 저장 경계 확정
- 삭제 즉시 새 분석에서 제외하고 실제 원문을 제거하는 생애주기 확정
- 성공·오류·재시도·안전 차단·재생성의 횟수 차감 규칙 확정
- 위기 표현에서 일반 캐릭터 답변을 중단하는 안전 상태 확정
- 공급자 설정, `store: false`, 데이터 공유 비활성화와 공개 고지 대조

완료 조건:

- 앱 화면·서버·DB·공급자 설정·개인정보처리방침이 같은 데이터 흐름을 설명한다.
- 정상·오류·삭제·동의 철회·위기 시나리오를 end-to-end로 검증할 수 있다.

### B. 주간 리포트 v1 계약

목적은 첫 구독의 대표 가치를 최소 화면과 최소 생성 비용으로 전달하는 것이다.

해야 할 일:

- 리포트가 사용하는 기록 유형·기간·최소 기록량 확정
- 사실 기반 돌아보기, AI 인사이트, 돌멩이의 편지의 역할 구분
- 상장·특별한 돌 등 소장·공유 결과물 중 첫 버전 하나 선택
- 기록이 적거나 없을 때의 대체 경험 확정
- 잘못된 해석의 숨김·피드백·재생성 규칙 확정
- 공유 이미지에서 원문과 민감한 맥락을 기본 제외
- 기존 리포트의 저장·재열람·삭제·해지 후 접근 규칙 확정

완료 조건:

- “왜 결제해야 하는가”를 한 문장으로 설명할 수 있다.
- 기록 충분·부족·없음·생성 실패·안전 차단 상태가 모두 정의돼 있다.
- AI가 사용자를 진단하거나 고정된 성격으로 단정하지 않는다.

### C. 권한과 콘텐츠 생애주기 계약

대상 상태:

```text
무료 · 체험 · 활성 구독 · 해지 예약 · 결제 유예/실패
만료 · 환불/회수 · 기존 구매자 평생 권한
```

해야 할 일:

- 상태별 새 AI·리포트 생성 권한 확정
- 기존 원본·AI 결과·리포트의 열람·수정·삭제 권한 확정
- 구매 복원, 기기 변경, iOS·Android 계정 연결 방식 확정
- 기존 구매자 식별 기준과 복구 절차 확정
- 환불·결제 실패·권한 만료 시 고객지원 기준 확정

완료 조건:

- 사용자가 만든 원본을 결제 상태 때문에 잃거나 열지 못하는 경우가 없다.
- 새로운 비용이 드는 생성 권한과 기존 콘텐츠 접근 권한이 분리돼 있다.

### D. 상품 묶음·체험·페이월 계약

첫 판단 순서는 다음과 같다.

1. 주간 리포트와 AI 사용량 차등만으로 구매 이유가 충분한지 본다.
2. 부족할 때만 구현 추정이 작은 기록 편의 기능을 추가한다.
3. 서로 다른 핵심 가치를 한 번에 검증해야 하는 기능은 후속으로 보낸다.

결정할 것:

- 첫 출시 필수 기능과 조건부 기능
- 무료 미리보기와 유료 전체 결과의 경계
- 체험 안에 실제 개인화 리포트가 도착하는 조건
- 사용자가 가치를 경험한 뒤 만나는 페이월 시점
- 체험 종료·해지 후 기존 결과 접근
- 상품 화면·스토어·약관에 동일하게 표시할 권한 문구

완료 조건:

- 상품 설명이 기능 목록이 아니라 사용자가 받는 결과를 중심으로 작성돼 있다.
- 체험 시작 전에 자동 갱신·가격·해지 조건을 이해할 수 있다.
- 체험 기간 안에 대표 유료 가치를 실제로 경험할 수 있다.

### E. 구현 인계와 출시 QA

해야 할 일:

- 채택한 계약과 현재 개발 브랜치의 차이를 파일·API·DB·화면 단위로 변환
- 개발자가 기능별 추정과 기술 위험을 독립적으로 제시
- 일정에 맞지 않으면 조건부 기능부터 제거하고 핵심 결과는 유지
- feature flag, 공급자 장애, 생성 실패와 긴급 중단 방법 확정
- 정책·스토어 라벨·앱 화면·코드의 데이터 처리 대조
- 계정 삭제, 기록 삭제, 구독 상태 전이와 구매 복원 QA

완료 조건:

- 개발자가 해석해야 하는 제품 질문이 남지 않는다.
- 모든 출시 차단 항목에 확인 담당자와 검증 방법이 있다.
- 롤백해도 사용자 원본과 결제 권한이 손상되지 않는다.

### F. 수요와 반복 사용 검증

측정해야 할 행동:

- 무료 AI 결과를 받은 사용자
- 무료 한도에 도달한 사용자와 이후 행동
- 리포트 생성 가능·열람·완독·재열람
- 페이월 노출·닫기·체험 시작·결제·취소·환불
- 공유 미리보기·공유 완료
- 기록 작성일 수와 D7 재방문

완료 조건:

- 체험 시작과 실제 결제를 분리해서 볼 수 있다.
- 기존 구매자와 신규 구독 수요를 분리할 수 있다.
- 기능 관심이 아니라 실제 결제 행동과 D7 행동으로 가설을 판단할 수 있다.

## 6. 범위 판단 기준

### 출시 기반으로 반드시 필요한 것

- 무료 AI의 데이터·안전·횟수 계약
- 주간 리포트의 최소 제품 계약
- 구독·체험·기존 구매자 권한과 구매 복원
- 개인정보 고지와 실제 데이터 흐름의 일치
- 결제·리포트·D7 측정 이벤트

### 개발 추정 후 포함할 수 있는 것

- 과거 날짜 기록
- 기록 한 건의 사진 수 확장
- 사용자가 자신에게 쓰고 나중에 받는 시간차 편지

이 기능들은 유용하지만 주간 리포트와 AI 사용량 차등의 개발·QA를 늦추면 먼저
제외한다.

### 이번 검증과 분리할 것

- 수첩 전체 구현과 장기 자기이해 변화 이력
- 돌멩이의 궁금증 전체 질문 체계
- 명상·호흡·바디스캔의 확장
- 외부 콘텐츠·문장 수집
- 꾸미기·음성·위젯·선물하기
- 심화 월간 리포트·영상·장기기억
- 전체 탭 구조를 한 번에 완성하는 작업

분리는 폐기가 아니다. 첫 유료상품의 구매 이유와 D7을 먼저 검증한 뒤 각 기능을
독립 가설로 다시 평가한다.

## 7. 결정 순서

다음 순서로 한 항목씩 결정하고, 뒤의 결정을 앞당겨 섞지 않는다.

1. 주간 리포트의 대표 결과와 최소 구성
2. 기록 부족·없음·오류 상태
3. 무료 미리보기와 유료 전체 결과
4. 상태별 권한과 해지 후 접근
5. 첫 상품의 필수·조건부·제외 기능
6. 체험과 페이월 시점
7. 개발 추정에 따른 범위 축소
8. 측정 이벤트와 출시 승인 조건

가격 숫자는 상품 가치·체험·권한·원가가 정리된 뒤 결정한다.

## 8. 출시 승인 게이트

| 게이트 | 통과 기준 |
| --- | --- |
| 제품 | 대표 유료 결과, 빈 상태, 실패 상태와 무료·유료 경계가 명확함 |
| 데이터 | 동의한 기록만 사용하고 삭제·철회가 새 분석에 반영됨 |
| AI 안전 | 사실과 해석을 구분하고 위기 상태에서 일반 답변을 중단함 |
| 개인정보 | 코드·공급자 설정·앱 안내·정책·스토어 표시가 일치함 |
| 결제 | 모든 권한 상태, 복원, 기존 구매자, 해지·환불을 테스트함 |
| 품질 | 핵심 경로와 실패·복구 경로를 실제 기기에서 검증함 |
| 측정 | 체험·결제·취소·D7과 핵심 기능 사용을 구분해 수집함 |

한 게이트라도 충족하지 못하면 기능 수를 줄인다. 데이터·결제·안전 게이트를
일정 때문에 생략하지 않는다.

## 9. 문서 갱신 규칙

- 채택된 제품 결정은 [페블링 제품 컨텍스트](../product-context.md)에만 기록한다.
- 이 문서는 작업 순서나 출시 게이트가 바뀔 때만 갱신한다.
- 기능별 상세 화면·문구·API·DB 명세는 승인 후 별도 실행 계약으로 작성한다.
- 진행률, 담당자, 현재 날짜별 할 일은 대시보드나 작업 관리 도구에서 관리한다.
- 외부 조사 결과는 `references`에 보존하고, 채택된 내용만 제품 문서로 옮긴다.
- 구현되지 않은 아이디어는 `ideation` 원본의 상태를 임의로 바꾸지 않는다.
