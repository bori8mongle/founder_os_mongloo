# 페블링 개발·기획 차이

## 결론

`origin/dev`에는 새로운 `털어놓기` 탭과 AI 관찰 기능이 상당 부분 구현되어 있고
기존 테스트도 통과한다. 그러나 최신 기획 저장소의 `속마음 엿보기` 계약보다 앞선
구버전 구조를 구현한 상태다. 따라서 “기능이 거의 완성됐다”와 “최신 제품·안전
기준으로 출시할 수 있다”를 구분해야 한다.

## 저장소 관계

- 앱 `main`: `0dac89b`
- 앱 `origin/dev`: `0805e98`
- `dev`는 `main`보다 135개 커밋 앞서고, `main`의 커밋을 모두 포함한다.
- 최신 AI 기획 `planing/main`: `9adadfb`
- 최신 기획 문서의 수정 시간이 개발 브랜치의 주요 병합보다 뒤이므로, 충돌 시
  현재 구현을 정답으로 보지 않고 최신 기획과 다시 합의해야 한다.

## 개발 브랜치에 구현된 범위

- 네 개 탭: 털어놓기, 뿌듯함, 관찰, 설정
- 털어놓기 온보딩, 대화형 입력, 돌멩이 프로필·꾸미기
- 기록 생성·조회·삭제
- AI 관찰 요청, 생성, 기록 목록·상세, 읽음 상태, 피드백, 삭제, 공유
- Supabase 테이블·RLS·Edge Function·운영용 Prompt Lab
- 실패·재시도·쿼터·안전 상태를 다루는 테스트

## 최신 기획과의 핵심 차이

| 항목 | 현재 `dev` 구현 | 최신 `planing` 기준 | 판단 |
| --- | --- | --- | --- |
| 기능 이름/경험 | 관찰 생성 중심의 구버전 명칭 흔적 | `속마음 엿보기`, 실시간 상담이 아닌 돌멩이의 짧은 속마음 | 제품 문구와 기대 재정렬 필요 |
| 출력 구조 | `title` + 단일 `body` | 3~7개 말풍선, 각 90자 이하, 총 420자 이하, 질문 최대 1개 | 응답·DB·UI·테스트 변경 |
| 결과 상태 | `normal`, `sensitive`, `dependency_buffer`, `crisis` | 일반 속마음, 속마음+안전 도움, 안전 화면만 | 상태 모델 교체 |
| 입력 범위 | 선택 날짜와 사용하지 않은 기록 중심 | 최근 사용자 원문 최대 20,000자 | 컨텍스트 선택 규칙 교체 |
| 최소 입력 | 80자 | 새 자유 텍스트 80자 | 유지하되 언어 테스트와 분리 |
| 제공 횟수 | DB 기본 무료 1회, 허용값 1/3회 | 무료 2회/일, 유료 5회/일은 비용 QA 후 후보 | 2회는 새 기준, 5회는 아직 확정 아님 |
| 모델 | stub/OpenAI/Gemini 구조 | v1은 OpenAI 한 공급자, 동일 모델 일시 오류 1회 재시도 | 공급자·폴백 정책 단순화 |
| 생성 계약 | JSON 텍스트 요청 후 파싱 | 구조화 출력 + 결정적 구조 검증 | 구현 변경 |
| 안전 검증 | 입력 및 상태 분기 중심 | 출력 Moderation + AI 평가 + 사람 검토 포함 | 출시 게이트 추가 |
| 미성년자 | 실행 시점 연령 정보 없음 | `under_18/adult/unknown` 컨텍스트 후보 | 수집·법적 근거·UX 결정 선행 |
| 안 읽은 결과 | 구버전 날짜 카드 규칙 | 저장된 미열람 결과를 최대 24시간 우선 | 조회 우선순위 변경 |

## 검증 결과

개발 브랜치 커밋 `0805e98`을 별도 임시 작업 복사본에서 검사했다.

- `npm run typecheck`: 통과
- 기존 앱·Edge Function·운영 스크립트 전체 테스트: `148/148` 통과
- 별도 털어놓기 테스트: `137/137` 통과
- Prompt Lab 테스트: `55/55` 통과

이 숫자는 현재 코드의 내부 일관성을 의미한다. 최신 `planing`의 말풍선·3단계
상태·240개 시나리오 계약을 만족한다는 증거는 아니다.

## 안전성 검증 현황

- 시나리오 은행은 총 240개다.
- 현재 파일 기준 `reviewed`는 27개, `draft`는 213개로 확인된다.
- 다른 기획 문서에는 30개 검토로 적힌 곳이 있어 숫자 정합성 확인이 필요하다.
- 승인된 골든 시나리오는 아직 없다.
- `속마음+안전 도움`, `안전 화면만` 결과의 검토 완료 사례가 없다.
- 현재 Prompt Lab은 구버전 출력·안전 상태를 검증하므로 최신 계약에 맞춘 P0
  재작업 대상이다.

## 유료상품 판단 전에 막아야 할 오해

- **무료 2회/유료 5회**: 5회는 상품 확정값이 아니라 비용 검증 전 후보다.
- **테스트 통과**: 최신 안전·품질 계약의 출시 승인을 뜻하지 않는다.
- **AI 기능 구현**: 현재 개인정보처리방침과 데이터 처리 방식이 맞춰졌다는 뜻이
  아니다.
- **기존 유료 회원 필드**: 실제 구독 entitlement, 영수증 검증, 복원, 환불
  처리가 구현됐다는 뜻이 아니다.

## 다음 구현 판단에 필요한 순서

1. 최신 출력·안전 상태를 하나의 제품 계약으로 확정
2. 입력 데이터 범위, 보관 시간, 삭제 연동, 모델 설정 확정
3. 240개 시나리오와 Prompt Lab을 새 계약으로 교체
4. 비용 QA로 유료 횟수 후보 검증
5. entitlement·구매 복원·해지·환불 구조 설계
6. 공개 정책과 App Store 개인정보 표시를 맞춘 뒤 출시 검토
