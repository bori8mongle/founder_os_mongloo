# 털어놓기 온보딩 제품 맥락

## 1. 문서의 역할

이 문서는 털어놓기 온보딩을 상세 기획하는 동안 결정 맥락을 잃지 않기 위한
단일 기준이다. 화면별 치수나 최종 문구를 확정하는 문서가 아니라 다음을
구분해 보존한다.

- 왜 기존 통합 온보딩을 축소하는지
- 현재 확정된 제품 정책
- 상세 기획에서 정의해야 하는 상태와 예외
- 이번 버전에서 의도적으로 제외한 기능

세부 화면 명세, 상태표와 QA 기준은 이 문서를 바탕으로 별도 산출물에서 정의한다.

## 2. 배경과 목표

기존에는 하나의 온보딩에서 털어놓기와 돌멩이를 설명하고, 돌멩이를 설정한 뒤
속마음까지 체험하게 했다. 이 구조는 온보딩이 길고, 중단·생성 실패·AI 동의 등
고려해야 할 분기가 많았다.

속마음은 현재 사용자 정보와 감정 반영이 제한적인 무료 초기 버전이다. 이를 첫
이용의 필수 가치로 강조하면 기대 수준을 과도하게 높이고, 사용자가 털어놓기
자체를 경험하기 전에 이탈할 수 있다.

따라서 이번 온보딩의 목표는 다음과 같다.

1. 앱 전체 기능은 별도의 짧은 통합 온보딩에서 소개한다.
2. 털어놓기 탭에 처음 들어와 실제로 사용하려는 시점에만 돌멩이를 설정한다.
3. 사용자가 빠르게 첫 이야기를 남기게 한다.
4. 속마음은 필수 체험이 아니라 사용 중 자연스럽게 발견하는 보조 경험으로 둔다.
5. 털어놓기와 속마음은 이번에 함께 처음 출시한다. 모든 사용자는 같은 최초 이용
   흐름을 거치며, 설정 완료 후 재진입은 서버 프로필 상태로 판단한다.

## 3. 제품 경험의 핵심 정의

### 털어놓기

사용자가 지금 떠오르는 생각과 감정을 편하게 남기는 공간이다. 돌멩이는 이
채팅 공간에서 사용자에게 바로 답하거나 조언하며 대화하지 않는다.

### 돌멩이의 속마음

사용자에게 보내는 답변이 아니라, 사용자가 남긴 최근 이야기를 돌멩이가 나중에
혼자 떠올린 생각이다. 사용자는 그 생각을 엿본다.

이 구분을 지키기 위해 다음 표현 원칙을 사용한다.

- 속마음을 `답변`, `답장`, `응답`이라고 부르지 않는다.
- 속마음을 사용자 메시지 바로 아래에 붙여 채팅 답변처럼 보이게 하지 않는다.
- 속마음은 별도 버튼과 결과 화면에서 제공한다.
- 돌멩이가 생각하는 장면은 일반 말풍선과 다른 생각구름으로 표현한다.

## 4. 확정된 범위와 정책

### 4.1 전체 구조

- 앱 최초 진입 시 모든 기능을 간단히 소개하는 통합 온보딩을 별도로 제작한다.
- 돌멩이 설정은 털어놓기 탭에서 처음 사용을 시작할 때 진행한다.
- 호칭은 필수로 받는다. 실명이 아니라 돌멩이에게 불리고 싶은 이름이다.
- 속마음 엿보기는 온보딩의 필수 단계로 넣지 않는다.
- 돌멩이를 탭했을 때 랜덤 문구를 보여주는 기능은 이번 범위에서 제외한다.
- 속마음에 사용자가 답하는 기능은 보류한다.
- 무료 버전에서도 VentHome 최초 진입 시 입력창 안내에 이어 `생각 엿보기`
  코치마크를 연속으로 보여준다.
- 피드백 버튼과 기존 피드백 흐름은 무료 버전에서도 노출한다.

### 4.2 돌멩이 설정

- 눈은 기본적으로 존재하며 `눈 없음` 상태를 제공하지 않는다.
- 머리 장식 목록의 첫 번째 option은 장식이 적용되지 않은 기본 돌멩이 이미지다.
- 사용자에게 `없음`이라는 텍스트 라벨을 별도로 노출하지 않는다.
- 장식을 해제하려면 첫 번째 기본 이미지를 직접 선택한다.
- 색상 3종, 눈 3종, 머리장식 에셋 5개를 사용한다. 머리장식 tab에는 장식 없는
  기본 이미지까지 포함해 총 6개 option을 노출한다.
- 머리장식 내부 key는 현재 Figma component suffix를 사용한다:
  `default`, `sprout`, `upset`, `cone`, `bald`, `weed`.
- 가로 선택 목록은 화면 너비와 관계없이 카드 3개 전체와 다음 카드 일부가 보여
  스크롤 가능성을 알 수 있게 한다.
- 장식은 하나를 단순 확대하지 않고 필요한 중간·큰 크기 자산을 별도로 제공한다.

### 4.3 설정 완료

- 완료 화면의 돌멩이 생각은 AI 생성이 아니다.
- 이름만 치환하는 규칙 기반 고정 문구를 사용한다.
- 일반 말풍선이 아니라 생각구름으로 표시해 `채팅에서 답하지 않음`과 충돌하지
  않게 한다.
- 설정 저장 성공 후에만 완료 화면을 보여준다.
- 완료 CTA는 `숲에서 이야기하기`처럼 다음 행동을 분명히 알리는 방향을 사용한다.

### 4.4 첫 이용 안내

확정한 노출 순서는 다음과 같다.

1. VentHome 최초 진입 즉시 배경을 dim 처리하고, 떠오르는 생각을 편하게 남기는
   입력창임을 알려준다.
2. 첫 안내에서 확인을 누르면 dim을 유지한 채 `생각 엿보기` 안내를 바로 이어
   보여준다. 아직 생성 가능 전일 수 있으므로 `이야기를 남기면 볼 수 있음`으로
   설명한다.
3. 첫 메시지를 보낸 직후, 돌멩이가 이곳에서 답하거나 조언하지 않는다는 사실을
   알려준다.
4. 첫 속마음이 성공적으로 생성된 뒤, 속마음의 의미를 1회 설명한다.

두 개의 최초 진입 코치마크를 모두 확인한 뒤 dim을 해제하고 사용자가 입력을
시작하게 한다. 각 확인 상태는 계정 기준으로 저장한다.

### 4.5 첫 속마음 설명

- 첫 속마음 생성 성공 후에만 1회 노출한다.
- 생성 전이나 실패 상태에서는 노출하지 않는다.
- 긴 텍스트 중심 바텀시트보다 짧은 삽화형 소개 또는 한 화면의 짧은 설명을
  우선한다.
- 사용자가 닫은 뒤 다음 속마음마다 반복하지 않는다.
- 이후에는 Info에서 다시 볼 수 있게 한다.
- 설명의 핵심은 `답변이 아닌 혼자 떠올린 생각`, `최근 이야기를 주로 기억함`,
  `마음에 닿는 생각만 받아들여도 됨` 세 가지다.

## 5. 설정 완료 여부별 진입 정책

상세 진입 결정표와 상태 판정 우선순위는
[털어놓기 온보딩 상태·저장·복구 명세](venting-onboarding-state-and-recovery.md)를
단일 원본으로 사용한다.

### 5.1 프로필이 없는 사용자

```text
앱 통합 온보딩
→ 털어놓기 탭 첫 사용
→ 짧은 소개
→ 돌멩이 외형 설정
→ 필수 호칭 설정
→ 저장 성공
→ 고정 속마음이 있는 완료 화면
→ 숲에서 첫 기록
```

### 5.2 설정을 완료한 사용자

- 유효한 서버 프로필이 있으면 설정이 완료된 것으로 판단하고 온보딩을 다시
  보이지 않는다.
- 설정 완료 화면을 확인했는지는 별도로 저장하지 않는다.
- 재설치·새 기기 로그인 시에도 유효한 서버 프로필이 있으면 온보딩을 건너뛴다.
- 털어놓기와 속마음은 함께 최초 출시하므로 사용자군별로 코치마크를 다르게
  노출하지 않는다. 모든 사용자가 같은 최초 이용 순서를 따른다.
- 프로필 조회가 실패하거나 필수값이 유효하지 않으면 신규 설정으로 덮어쓰지 않고
  공통 오류와 `다시 시도`를 보여준다.

## 6. 중단·실패 복구 원칙

단계별 저장 시점과 플랫폼 뒤로가기를 포함한 상세 계약은
[털어놓기 온보딩 상태·저장·복구 명세](venting-onboarding-state-and-recovery.md)를
단일 원본으로 사용한다.

| 상황 | 처리 원칙 |
| --- | --- |
| 설정 중 앱 완전 종료 | 서버 프로필이 없으면 처음부터 다시 설정 |
| 설정 화면 안에서 뒤로가기 | 현재 앱 세션의 선택값과 입력값 유지 |
| background 전환 | 프로세스가 살아 있으면 현재 화면과 값 유지 |
| 저장 실패 | 화면과 입력값을 유지하고 오류와 재시도 제공 |
| 완료 버튼 연속 탭 | 중복 저장 방지 |
| 프로필 저장 성공 후 앱 종료 | 온보딩 완료로 유지하고 다음 실행은 VentHome으로 이동 |
| 저장 중 앱 종료 | 다음 실행에서 서버 프로필을 조회해 완료 또는 처음부터 시작 |
| 오프라인 | 저장 실패로 처리하며 자동 동기화나 영구 임시 저장은 제공하지 않음 |
| 새 기기·재설치 | 유효한 서버 프로필이 있으면 온보딩 건너뜀 |

무료 v1에서는 영구 로컬 draft, `이어서 설정하기`, 오프라인 자동 동기화 queue와
timeout 전용 복구 화면을 만들지 않는다.

## 7. 호칭 정책

상세 기획의 기본안은 다음과 같다.

- 제품 용어는 `이름`보다 `호칭`을 우선한다.
- 1~10자, 앞뒤 공백 제거, 공백만 입력 금지
- 한글(자모 포함)·영문·공백만 허용
- 숫자·일반 이모지·특수문자 미허용
- 전화번호·이메일처럼 직접 식별정보로 보이는 입력은 안내 후 제한
- 실명 입력이 필수가 아님을 설명
- 조사 처리는 현재 앱의 받침 판별 규칙을 재사용
- 조사 처리가 불안정한 문자와 이모지에는 조사 없는 문장 사용

이 규칙과 실제 입력 오류 문구를 Figma에 함께 기재한다.

## 8. 속마음 버튼 상태

코치마크로 강조하지 않더라도 다음 상태의 UI와 행동을 정의해야 한다.

1. 생성 조건 미충족
2. 생성 가능
3. 생성 중
4. 생성 완료
5. 오늘 이용 횟수 소진
6. 네트워크 오류
7. 생성 실패
8. AI 분석 동의 없음

비활성 버튼을 눌렀을 때 무반응으로 끝내지 않고 짧은 이유를 알려준다. 정확한
생성 조건, 일일 횟수와 초기화 기준은 속마음 제품 계약의 단일 원본을 따른다.

## 9. Info와 설정 변경

Info는 다음 내용을 다시 확인하는 진입점이다.

- 털어놓기는 어떤 공간인지
- 돌멩이가 채팅으로 답하지 않는 이유
- 속마음은 무엇인지
- 최근 이야기를 중심으로 생각한다는 점
- AI 기능과 데이터 처리 안내로 이동하는 링크
- 내 돌멩이 설정 변경 진입점

외형과 호칭은 나중에 변경할 수 있게 한다. 변경해도 기존 기록과 속마음 결과는
유지한다. 과거 AI 결과의 문장은 생성 당시 결과로 보존하고, 현재 호칭으로
소급 변경하지 않는 것을 기본 원칙으로 한다.

## 10. 데이터·개인정보 원칙

- 외형·호칭은 프로필로 저장하고, 코치마크 확인 상태는 별도로 저장한다.
- 온보딩 완료는 별도 화면 확인값이 아니라 유효한 서버 프로필로 판정한다.
- AI 분석 동의는 속마음 첫 생성 전에 확인한다.
- 동의하지 않아도 털어놓기 기록 저장·조회는 사용할 수 있게 한다.
- 호칭과 기록 원문을 분석 이벤트에 넣지 않는다.
- 완료 화면의 고정 속마음은 AI 호출이나 AI 분석 동의를 요구하지 않는다.
- 모든 사용자는 속마음 AI 기능을 처음 실행하려는 시점에 현재 시행 중인
  개인정보처리방침과 AI 분석 동의 상태를 확인한다.

## 11. 최소 측정 항목

- 돌멩이 설정 시작·완료·중단 단계
- 단계별 이탈
- 호칭 저장 성공·실패
- 첫 메시지 작성 완료
- 코치마크 노출·닫기
- 속마음 버튼 최초 진입
- 첫 속마음 생성 시도·성공·실패
- 첫 속마음 설명 확인
- Info 재진입

분석 이벤트에는 사용자 원문, 호칭과 직접 식별정보를 넣지 않는다.

## 12. UI·접근성 필수 검수

- 작은 화면과 큰 화면의 가로 선택 목록 노출 규칙
- 선택 상태를 색상만으로 구분하지 않는 표시
- 돌멩이 미리보기와 실제 숲 사이의 크기·위치 일관성
- 키보드가 올라왔을 때 호칭 입력창과 완료 버튼의 가시성

### 현재 구현과의 핵심 차이

- 앱의 기존 3장 온보딩을 단일 소개 화면으로 교체해야 한다.
- 현재 설정 데이터에는 머리장식 field가 없으며 색상·눈만 저장한다.
- 현재 저장 성공 경로는 `VentingShare`이며 신규 `VentSetupComplete` route가 없다.
- 현재 프로필 row가 완료의 근거다. 완료 전 영구 로컬 draft와 이어하기는 추가하지
  않고, 앱 종료 시 처음부터 다시 설정한다.
- 계정별 코치마크 확인 상태 저장은 현재 코드에서 확인되지 않았다.
- 현재 호칭 입력은 한글·영문·공백만 허용한다. 최종 허용 문자 정책과 맞춰야 한다.

### 1단계 결정 결과

1. 호칭은 한글(자모 포함)·영문·공백만 허용한다.
2. 프로필 저장 성공 후 앱이 종료되면 완료 화면을 반복하지 않고 VentHome으로
   이동한다. 별도 `completion_seen` 상태는 만들지 않는다.
3. 머리장식 에셋 5개와 장식 없는 기본 이미지 1개가 완성됐다. 선택 option은 총
   6개이며 Figma component suffix를 내부 key로 사용한다: `default`, `sprout`,
   `upset`, `cone`, `bald`, `weed`. 구현은 option 개수에 의존하지 않는 가로
   목록으로 만든다.
4. VentHome 최초 진입 즉시 Chat 코치마크를 dim 상태로 보여주고, 확인하면 Peek
   코치마크를 바로 이어 보여준다. 두 번째 확인 후 dim을 해제한다. 털어놓기와
   Peek는 함께 최초 출시하므로 모든 사용자가 동일한 순서를 따른다.
5. 무료 v1에서도 속마음 결과의 피드백 버튼을 노출한다.
6. 완료 전 설정값은 현재 앱 세션에서만 유지한다. 앱을 완전히 종료하면 처음부터
   다시 설정하며, 영구 로컬 draft·이어하기·오프라인 동기화를 추가하지 않는다.
7. 프로필 조회 중·유효함·없음·오류를 UI에서 구분한다. 저장 실패 시 현재 화면과
   값을 유지하고 재시도하며, 유효한 서버 프로필을 온보딩 완료의 기준으로 사용한다.
