# 털어놓기 온보딩 상태·저장·복구 명세

## 1. 이번 버전의 결론

털어놓기 설정은 짧은 흐름이므로 별도의 복구 시스템을 만들지 않는다.

- 설정 중 선택값과 호칭은 현재 앱 화면이 살아 있는 동안만 유지한다.
- 완료 전 앱을 완전히 종료하면 다음 실행에서 처음부터 다시 설정한다.
- 마지막 `완료`에서 외형과 호칭을 서버에 한 번 저장한다.
- 저장에 실패하면 현재 화면과 입력값을 유지하고 다시 시도할 수 있게 한다.
- 앱을 종료한 뒤의 완료 여부는 완료 화면을 봤는지가 아니라 유효한 서버 프로필로
  판단한다.

이번 버전에는 다음 기능을 만들지 않는다.

- 설정값의 영구 로컬 임시 저장
- `이어서 설정하기`
- 오프라인 저장 대기열과 자동 동기화
- timeout 전용 복구 상태나 별도 손상 프로필 화면

## 2. 현재 앱에서 확인한 기준

확인 기준일은 2026-08-09이며, 읽기 전용 `pebbling-expo/`를 확인했다.

| 항목 | 현재 구현 |
| --- | --- |
| 완료 판정 | `journal.venting_profiles`에 사용자 프로필이 있으면 완료로 판단 |
| 최종 저장 | 호칭 완료 시 외형과 호칭을 한 번에 서버에 저장 |
| 설정 중 값 | React 화면 state에만 있어 앱을 완전히 종료하면 사라짐 |
| 저장 실패 | 현재 화면에 머물며 입력값과 선택값이 유지됨 |
| 프로필 조회 | 조회 중·오류·프로필 없음이 기술적으로는 구분됨 |
| 현재 UI의 부족한 점 | 조회 중이나 오류를 프로필 없음처럼 보여줄 수 있어 상태별 화면 구분이 필요함 |
| 머리장식 | API·DB 저장 필드가 아직 없음 |

새 복구 저장소를 만드는 것보다 현재 패턴을 유지하고, 프로필 조회 상태를 UI에서
정확히 구분하는 것이 이번 버전의 최소 변경이다.

## 3. 털어놓기 탭 진입 상태

앱은 서버 프로필 조회 결과를 확인한 뒤 다음 화면을 보여준다.

| 서버 확인 상태 | 사용자 화면 | 행동 |
| --- | --- | --- |
| 조회 중 | 로딩 | 설정 시작 버튼을 미리 보여주지 않음 |
| 유효한 프로필 있음 | 완료된 VentHome | 온보딩과 완료 화면을 건너뜀 |
| 프로필 없음이 확인됨 | 미완료 VentHome | `시작하기`로 설정 진입 |
| 조회 실패 | 오류 안내 | `다시 시도` 제공, 신규 사용자로 추측하지 않음 |
| 프로필 값이 유효하지 않음 | 오류 안내 | 조회 실패와 같은 공통 오류·재시도 사용 |

오류 문구는 기술 원인을 노출하지 않고 다음 수준으로 통일한다.

> 설정 정보를 확인하지 못했어요. 잠시 후 다시 시도해 주세요.

## 4. 설정과 저장 흐름

```text
미완료 VentHome
→ 소개
→ 외형 선택
→ 호칭 입력
→ 저장 중
→ 설정 완료
→ 완료된 VentHome
```

| 단계 | 사용자 행동·결과 | 처리 |
| --- | --- | --- |
| 소개 | 설정 시작 | 외형 선택으로 이동 |
| 외형 선택 | 색·눈·머리장식 선택 | 현재 화면 state에만 유지 |
| 외형 선택 | 다음 | 선택값을 가진 채 호칭 입력으로 이동 |
| 호칭 입력 | 뒤로가기 | 선택값과 입력값을 유지한 채 외형 선택으로 이동 |
| 호칭 입력 | 유효한 호칭으로 완료 | 저장 중으로 전환 |
| 저장 중 | 처리 중 | 완료 버튼을 로딩·비활성화하고 뒤로가기 차단 |
| 저장 성공 | 유효한 프로필 생성 | 설정 완료 화면 표시 |
| 저장 실패 | 네트워크·검증·서버 오류 | 현재 화면과 값 유지, 오류 문구와 재시도 제공 |
| 설정 완료 | `숲에서 이야기하기` | 완료된 VentHome으로 이동 |

## 5. 앱 종료와 재진입

| 종료 시점 | 다음 실행 결과 |
| --- | --- |
| 소개·외형·호칭 입력 중 종료 | 서버 프로필이 없으므로 처음부터 다시 설정 |
| 앱을 background로만 전환 | 프로세스가 살아 있으면 현재 화면과 값 유지 |
| 저장 중 앱 종료 | 다음 실행에서 서버 프로필을 다시 조회 |
| 저장 요청이 성공한 상태 | 완료된 VentHome으로 진입 |
| 저장 요청이 완료되지 않은 상태 | 프로필 없음 확인 후 처음부터 다시 설정 |
| 저장 성공 후 완료 화면에서 종료 | 완료 화면을 반복하지 않고 VentHome으로 진입 |

핵심 판정 기준은 **유효한 서버 프로필의 존재 여부**다. 완료 화면을 봤는지 기록하는
별도 필드는 만들지 않는다.

## 6. 저장되는 값

마지막 `완료`에서 다음 값을 한 번에 서버에 저장한다.

- `user_id`
- `pebble_color`
- `pebble_face`
- 머리장식 key
- `call_name`
- `onboarding_completed_at`

호칭은 앱 기준과 동일하게 1~10자, 한글(자모 포함)·영문·공백만 허용한다. 숫자,
일반 이모지와 특수문자는 허용하지 않는다.

기존에 완료된 프로필은 신규 온보딩 저장으로 덮어쓰지 않아야 한다. 중복 저장을
막는 구체적인 구현 방법은 현재 API·DB 구조를 확인해 개발 단계에서 선택한다.

## 7. 기존 사용자와 머리장식 기본값

- 유효한 기존 프로필이 있으면 온보딩을 다시 보여주지 않는다.
- 기존 기록, 호칭, 색과 눈은 유지한다.
- 기존 프로필에 머리장식 값이 없으면 `default`를 적용한다.
- 머리장식 값이 없다는 이유로 기존 사용자를 설정 화면으로 강제 이동시키지 않는다.
- 새 기기나 재설치 뒤에도 서버 프로필이 있으면 설정을 건너뛴다.

## 8. 버튼과 오류 상태

### 완료 버튼

- 기본: 호칭이 유효할 때 활성화
- 비활성: 빈 값 또는 허용되지 않은 문자가 있을 때
- 저장 중: 로딩 표시, 연속 탭과 뒤로가기 차단
- 저장 실패: 로딩 해제, 입력값 유지, 오류 문구 표시 후 다시 시도 가능

### 저장 실패 문구

> 저장하지 못했어요. 잠시 후 다시 시도해 주세요.

필드 검증 오류처럼 사용자가 직접 수정할 수 있는 경우에만 해당 입력 규칙을 구체적으로
안내한다.

## 9. 뒤로가기

- 설정 화면의 iOS swipe back은 비활성화한다.
- Android 시스템 뒤로가기는 화면의 헤더 뒤로가기와 동일하게 처리한다.
- 외형과 호칭 화면을 오가는 동안에는 현재 세션의 선택값과 입력값을 유지한다.
- 저장 중에는 뒤로가기와 화면 닫기를 막는다.
- 앱 강제 종료는 막지 않으며 다음 실행에서 서버 프로필로 완료 여부를 판단한다.

## 10. 구현·QA에서 반드시 확인할 것

1. 프로필 조회 중·없음·오류·유효함이 서로 다른 화면으로 표시되는가
2. 저장 실패 뒤 외형과 호칭이 현재 화면에 유지되는가
3. 완료 버튼을 연속으로 눌러도 저장 요청이 중복되지 않는가
4. 저장 중 앱 종료 뒤 서버 저장 결과에 따라 정확히 분기되는가
5. 기존 사용자에게 `default` 머리장식이 적용되고 온보딩이 다시 뜨지 않는가
6. 완료 화면을 본 여부와 관계없이 서버 프로필이 있으면 완료로 판단하는가
