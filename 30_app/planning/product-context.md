# 페블링 제품 컨텍스트

## 1. 이 문서의 역할

이 문서는 페블링의 상세 기획을 모두 복제하는 문서가 아니다. 현재 무엇이
사실이고, 무엇을 결정했으며, 무엇을 검토 중인지 한 번에 파악하고 관련 원본으로
이동하기 위한 **제품 판단 허브**다.

현재 최우선 과제는 2026년 8월의 첫 구독 수요 검증이지만, 단기 상품 기획이
장기적인 제품 방향과 충돌하지 않도록 전체 제품 맥락을 함께 관리한다.

### 상태 표기

| 상태 | 의미 |
| --- | --- |
| `사실` | 코드·공개 서비스·문서에서 확인했거나 김세인이 현재 상황으로 확인한 내용 |
| `결정` | 김세인이 명시적으로 채택한 제품 방향 |
| `방향` | 선호하는 방향은 있으나 세부 계약이 확정되지 않은 내용 |
| `가설` | 사용자 반응이나 데이터로 검증해야 하는 예상 |
| `후보` | 비교·검토 중이며 아직 채택되지 않은 기능이나 구조 |
| `질문` | 답에 따라 설계·일정·상품 경계가 달라지는 미해결 사항 |

`결정`은 구현이나 배포를 뜻하지 않는다. 구현·배포 여부는 별도의 `사실`로
확인한다. Figma 화면의 완성도와 배치 위치도 채택 상태를 뜻하지 않는다.

제품 상태와 근거 수준은 분리한다. 이 문서에서 별도 원본이 표시되지 않은
팀·일정·사업·상품 관련 사실과 결정은 김세인이 2026-07-26까지 대화에서 확인한
내용이다. 정부지원사업의 외부 공고·평가 세칙은 이 문서 작성 과정에서 별도로
재검증하지 않았다.

## 2. 현재 상황 한눈에 보기

- `사실` 현재 앱은 뿌듯함과 불편함을 기록하고 이를 돌·돌탑과 기록 화면으로
  다시 보게 한다.
- `방향` 장기적으로 기록을 자기 지지와 자기이해로 연결하려 한다.
- `사실` 2026-07-25 확인 기준 App Store 공개 버전은 iOS `1.2.6`이다.
- `사실` Expo 전환은 완료됐고, Android 신규 출시는 2026-07-26 기준 다음 주를
  목표로 한다. 정확한 출시일과 실제 배포 완료 여부는 다시 확인해야 한다.
- `사실` 현재 배포 제품의 중심 경험은 `뿌듯함 기록·돌탑`과
  `불편함 관찰하기·나에게 한마디`다.
- `사실` 개발 브랜치에는 `털어놓기`와 AI 관찰 경험이 구현돼 있지만,
  2026-07-25 기준 최신 `속마음 엿보기` 기획 계약과 차이가 있다.
- `결정` `돌멩이의 속마음`은 구독보다 먼저 무료 기능으로 출시한다.
- `결정` 무료 `돌멩이의 속마음` 출시 목표는 2026-08-05까지다.
- `결정` 무료 사용자는 AI 답변을 하루 2회, 구독 사용자는 하루 10회 이용하는
  방향이다. 실제 코드·비용·쿼터 초기화 규칙은 출시 전에 맞춰야 한다.
- `결정` 기존에 앱을 3,900원에 구매한 사용자는 반복 구독 없이 구독자와 같은
  평생 권한을 받는다.
- `결정` 첫 시장은 한국어·한국 사용자다.
- `방향` 첫 유료상품은 월간·연간 구독을 중심으로 검토하며, RevenueCat 사용이
  초안이다. 가격·3개월 상품·무료 체험 적용 범위는 아직 확정되지 않았다.

상세한 배포·개발·법적 기준은
[유료상품 기획 기준](paid-products/README.md)과 그 하위 문서를 우선해서 본다.

## 3. 사업 배경과 이번 검증의 목적

### 정부지원사업 일정

- `사실` 예비창업패키지 1단계는 2026년 6~9월이다.
- `사실` 2026년 9월 중간평가에서 약 50%가 탈락하며, 통과 시
  2026년 10월~2027년 1월의 2단계 지원으로 이어진다.
- `결정` 2026년 8월 말까지 유료 결제 수요를 수치로 증명하는 것이 가장 중요한
  단기 사업 목표다.
- `결정` 첫 구독상품은 2026년 8월 14일 출시를 목표로 하고, 수요 검증 기간을
  확보하기 위한 최종 출시 한계는 8월 17일로 둔다.
- `질문` 첫 유료상품의 최소 범위는 아직 확정하지 않았다.

### 성공을 판단하는 현재 기준

| 항목 | 현재 기준 | 상태 |
| --- | --- | --- |
| 수요 증명 | 2주 안에 실제 결제 또는 7일 무료 체험 시작 합계 100건 이상 | `결정` |
| 인정 가능한 행동 | 실제 결제 또는 7일 무료 체험 시작 모두 사업 증빙에 활용 가능 | `사실` |
| 제품 지표 | D7 리텐션을 먼저 확인하고 이후 D15까지 확장 | `결정` |
| 장기 목표 | 반복 사용과 고착도 향상 | `결정` |
| 마케팅 계획 | 제품 범위와 별도로 나중에 설계 | `결정` |

`100건`은 아직 운영 지표로 완전히 정의되지 않았다. 고유 사용자 기준, 기존
구매자 제외 여부, 환불·취소 처리, 실제 결제와 체험 시작을 합산하는 방식,
측정 시작일과 종료일을 출시 전에 확정해야 한다.

## 4. 팀과 제약

| 영역 | 현재 상태 |
| --- | --- |
| 기획·디자인·운영·QA·고객응대·AI 품질 기준 | 김세인 |
| 개발 | 풀스택 개발자 1명과 단기 외주 개발자 |
| AI 품질 보조 | Codex·Claude 등 |
| 법률·임상 안전 | 상시 담당자 확인되지 않음 |
| 개발비·월 AI 운영비 | 상한 미확정 |
| 핵심 시간 제약 | 2026-08-05까지 무료 속마음 출시, 8월 말까지 유료 수요 증빙 |

따라서 첫 버전은 “좋아 보이는 기능의 총합”이 아니라, 구독 이유를 설명하고
측정할 수 있는 가장 작은 가치 묶음이어야 한다. 안전·개인정보·결제 권한처럼
출시를 막는 기반 작업은 화면 수가 적어도 우선한다.

## 5. 제품이 해결하려는 문제

페블링이 반복해서 탐색해 온 문제는 다음 세 층으로 요약된다.

1. **지금의 경험을 놓치지 않기**
   - 잘한 일, 좋았던 순간, 불편함, 감정, 생각을 짧게 포착한다.
2. **경험과 거리를 두고 의미를 발견하기**
   - 사용자가 스스로 관찰하고 자기대화를 하며, AI는 근거가 있는 질문·해석을
     보조한다.
3. **쌓인 기록을 다시 돌려받아 나를 이해하기**
   - 돌탑, 수첩, 문장, 리포트, 편지처럼 재발견 가능한 형태로 되돌려 준다.

첫 유료상품의 핵심 가설은 단순히 기록 용량을 늘리는 데 있지 않다.
**이미 쌓인 기록을 개인화된 의미와 기억할 만한 결과물로 돌려주는 것**이
구독 이유가 될 수 있는지를 검증하는 것이다.

## 6. 공통 정보 모델 — 분석 제안

기능 이름보다 먼저 아래 정보 유형을 구분한다. 같은 원본을 여러 화면에서
재사용할 수 있지만, 불필요한 복사본은 만들지 않는다. 이 구분은 앞으로의
논의를 위한 분석 모델이며 아직 확정된 데이터 명세는 아니다.

| 정보 유형 | 설명 | 예시 | 기본 원칙 |
| --- | --- | --- | --- |
| 원본 경험 | 사용자가 그때 남긴 사실·감정·생각 | 뿌듯함, 불편함 관찰, 채팅, 이모지, 사진, 질문 답변 | 원문과 작성 시점을 보존 |
| 수집물 | 외부 또는 스스로 만든 보관 대상 | 문장, 링크, 누군가의 한마디 | 작성자·출처를 보존 |
| 자기이해 | 사용자가 확인한 자신에 대한 지식 | 좋아하는 것, 힘들어하는 것, 도움이 되는 것, 가치 | AI가 자동 확정하지 않음 |
| 주기 결과물 | 여러 원본을 일정 기간 단위로 해석한 것 | 주간 리포트, 상장, 돌멩이의 편지, 월간 회고 | 근거와 AI 해석을 구분 |

`회복 자원`은 별도의 원본 유형보다 문장·자기대화·도움이 된 행동·호흡법에
부여할 수 있는 **활용 역할**에 가깝다. `호흡법`은 재노출할 콘텐츠이고,
실제로 호흡한 `세션`은 사용 행동 기록이므로 구분한다.

### 기록의 생애주기

```text
포착 → 표현 → 의미 부여 → 보관 → 재열람 → 시간차 재해석 → 정기 통찰
```

### 하나의 원본을 연결하는 예시

```text
불편했던 사건 원본
├─ 관찰하기: 당시 상황·감정·나에게 한마디를 다시 보기
├─ 수첩 후보: “나는 갑작스러운 일정 변경을 힘들어한다”
├─ 쉼: 그때 도움이 됐던 문장을 다시 보여주기
└─ 주간 리포트: 반복 맥락을 근거와 함께 요약
```

핵심 원칙은 다음과 같다.

> 입력한 장소, 원본을 보관하는 장소, 다시 꺼내보는 장소는 같을 필요가 없다.
> 하나의 원본을 연결해 여러 목적에 맞게 보여준다.

### 질문에서 자기이해로 이어지는 흐름

```text
돌멩이의 궁금증
→ 사용자의 날짜별 답변 원본
→ 다른 기록과 함께 주간·장기 맥락에서 연결
→ AI 또는 사용자가 자기이해 후보를 제안
→ 사용자가 확인·수정
→ 수첩의 자기이해
→ 다음 질문·작은 실천·돌탑의 주의 방향
```

질문 답변은 수첩 문장이 아니다. 질문별 답변은 날짜가 있는 원본으로 누적하고,
그 답변에서 발견한 가치·특성·회복법만 사용자 확인 후 수첩에 저장한다. 과거
답변의 수정·삭제와 자기이해의 변화 이력을 어떻게 보존할지는 데이터 명세에서
추가로 결정한다.

### AI 처리와 저장 경계

`결정` 첫 유료상품과 무료 `돌멩이의 속마음`에서는 **서비스를 위한 기록
저장**과 **모델 학습**을 분리한다.

| 데이터 | v1 처리 원칙 |
| --- | --- |
| 사용자가 작성한 원본 기록 | 다시 보기·수정·삭제·동기화·리포트 생성을 위해 페블링 DB에 원본 1개를 저장 |
| AI가 만든 속마음·주간 리포트 | 사용자가 다시 볼 수 있도록 제품 결과를 저장 |
| 생성 근거 메타데이터 | 사용된 기록 ID, 생성 시각, 모델·프롬프트·정책·동의 버전을 최소한으로 저장 |
| AI 요청용 전체 프롬프트·원문 복사본 | 처리 중에만 만들고 별도 DB·분석·오류 로그에 저장하지 않음 |
| 범용 모델 학습·제공자 데이터 공유 | 사용하지 않음 |
| 장기기억·임베딩·자동 확정 심리 프로필 | v1에서 만들지 않음 |
| 실제 사용자 원문을 사용한 내부 QA | 자동 사용하지 않음. 필요하면 별도 안내·동의·접근·보존·삭제 계약 후 진행 |

권장 처리 흐름은 다음과 같다.

```text
원본 기록 저장
→ 사용자가 동의한 기능·기록 범위 확인
→ 필요한 원문으로 일시적 AI 요청 생성
→ 외부 AI 추론
→ 요청용 복사본 폐기
→ 사용자에게 보여줄 결과와 최소 메타데이터 저장
```

주간 리포트는 별도의 숨은 `AI 기억`을 상시 축적하지 않고, 생성 시점에 동의했고
삭제·제외되지 않은 해당 기간 원본을 조회한다. 삭제한 기록은 새로운 AI 생성과
리포트에서 즉시 제외하고, 짧은 복구기간을 제공한다면 그 기간이 지난 뒤 원문
본문을 실제로 제거해야 한다.

2026-07-26 확인 기준 OpenAI API 입력·출력은 명시적 공유 동의가 없으면 범용
모델 학습에 사용되지 않지만, 기본 오남용 모니터링 로그가 최대 30일 보관될 수
있다. 운영 요청에는 `store: false`를 명시하고 데이터 공유 설정을 끄되,
`어디에도 저장되지 않는다`고 안내하지 않는다. 공급자 정책과 실제 계정 설정은
출시 전에 다시 확인한다.

## 7. 현재 기능과 개발 상태

### 공개 제품에서 확인된 기능

| 기능 | 현재 역할 | 상태와 주의사항 |
| --- | --- | --- |
| 뿌듯함 기록 | 작은 성취·잘한 일을 텍스트, 사진, 태그로 기록 | `배포됨` |
| 월별 돌탑 | 기록을 돌멩이로 쌓아 축적을 시각화 | `배포됨` |

| 로그인·공지·계정 삭제·분석 | 서비스 공통 기반 | `배포됨` |

버전, 암호화, 사진 저장과 분석 이벤트에 대한 상세 사실은
[배포 제품 기준선](paid-products/01-deployed-product-baseline.md)을 본다.

## 8. 첫 유료상품 후보

현재 후보는 모두 같은 확정 수준이 아니다.

| 후보 | 현재 방향 | 기대하는 구독 가치 | 남은 핵심 결정 |
| --- | --- | --- | --- |
| 돌멩이의 속마음 | 무료 2회/일, 유료 10회/일 | 사용자의 기록을 바탕으로 더 자주 생각을 돕는 AI 경험 | 비용 상한, 쿼터 초기화, 안전·개인정보 출시 게이트 |
| 기록 사진 확장 | 기록 1개당 최대 20장 | 중요한 순간을 충분히 보관 | DB·업로드·정렬·삭제·부분 실패, 무료 한도와 유료 경계 |
| 과거 날짜 기록 | 이전 날짜에도 기록 가능 | 놓친 경험을 다시 보완 | 허용 범위, 리포트 집계 기준 |
| 기록 주제 확장 | 뿌듯함 외 좋았던 순간·감사·기쁨·배움 등 | 기록 빈도와 리포트 재료의 다양성 증가 | 명칭, 선택 태그, 돌탑의 정체성 |
| 주간 리포트 | 동의한 여러 기록 유형을 사용한 돌아보기·인사이트·편지·보상 | “앱이 나를 기억하고 이해한다”는 가장 강한 개인화 가치 | 최소 구성, 근거·해석 구분, 생성 실패·기록 부족 처리 |
| 시간차 편지 | 사용자가 자신에게 쓴 말을 다음 날 채팅에서 수신 | 내가 한 말이 다시 나에게 돌아오는 차별점 | 유료 범위, 작성·수신·보관 위치 |

현재 앱은 단일 사진 선택·단일 경로 저장 구조이므로 20장 지원은 단순한 숫자
변경이 아니다. DB, 업로드 순서, 삭제, 일부 사진만 실패한 경우의 UI까지 포함한
별도 기능 개발로 추정해야 한다.

### 서로 다른 두 종류의 편지

혼동을 막기 위해 두 기능을 분리한다.

1. **나에게 쓰는 편지**
   - 작성자: 사용자
   - 수신자: 미래의 사용자
   - 현재 아이디어: 다음 날 채팅에서 받기
2. **돌멩이가 보내는 편지**
   - 작성자: AI 캐릭터
   - 재료: 한 주 동안의 사용자 기록
   - 현재 아이디어: 주간 리포트의 정서적 결과물

둘은 작성 주체·기대·개인정보 처리·보관 방식이 다르므로 하나의 기능명으로
합치지 않는다.

## 9. 주간 리포트 방향

`방향` 주간 리포트는 첫 유료상품에서 가장 중요한 구매 이유 후보다.
숫자 통계만 보여주는 보고서보다, 사용자가 놓친 의미를 발견하고 소장·공유하고
싶은 결과를 주는 것이 핵심이다.

### 현재 확인된 요구

- 돌탑·관찰·채팅·이모지·편지 등 가능한 모든 기록 **유형**을 지원하고 싶다.
- 실제 개별 기록은 사용자가 포함 범위와 목적에 동의한 경우에만 사용하며,
  삭제·제외·동의 철회 상태를 반영해야 한다.
- AI가 만든 개인화 내용이 가장 큰 임팩트를 담당해야 한다.
- `주간 돌아보기`, `주간 인사이트`, `돌멩이의 편지`가 후보에 있다.
- 상장이나 특별한 돌처럼 공유하고 싶어지는 결과물을 탐색한다.
- 기본 발행 시점은 매주 월요일 오전 4시다.
- 유료 사용자가 원하면 일요일에 미리 생성하는 방식은 `후보`다.
- 단순한 첫 버전을 빨리 출시하고, 실제 반응을 보며 고도화한다.

### 제품 안에서의 위치

`결정` 주간 리포트는 돌탑의 하위 기능이 아니다. 돌탑만 분석하는 결과가 아니라
사용자가 분석 목적에 동의한 털어놓기·돌탑·관찰·질문 답변 등 여러 원본을
가로지르는 **통합 자기이해 결과물**이다.

주간 리포트는 `알아가기` 안에서 `돌멩이의 궁금증`, `수첩`과 동등한 하위
기능으로 둔다.

- 돌멩이의 궁금증: 자주 답하며 자기이해의 원재료를 만드는 입력
- 주간 리포트: 여러 원재료를 기간 단위로 연결하는 해석
- 수첩: 사용자가 현재 맞다고 확인한 자기이해를 장기 보관·갱신

평소에는 질문을 먼저 보여주고, 월요일 리포트가 도착한 시점에는 리포트 진입을
가장 위에 노출하는 동적 우선순위를 검토한다. 정확한 첫 화면 배치와 알림 방식은
화면 기획에서 확정한다.

### 최소 제품 계약에서 결정할 것

1. 어떤 기록을 포함하며 사용자가 이를 어떻게 확인·동의하는가
2. 기록이 적거나 없는 주에 무엇을 보여주는가
3. 관찰된 사실, AI 해석, 응원 문구를 어떻게 구분하는가
4. 잘못된 해석을 숨기거나 수정하고 피드백하는 방법
5. 상장·돌·편지 중 첫 출시 결과물의 우선순위
6. 공유 이미지에서 민감한 원문을 기본적으로 제거하는 방법
7. 해지 후에도 기존 리포트·편지를 계속 열람하되, 수정·재생성·내보내기 중
   어디까지 허용하는가
8. 리포트에서 발견한 자기이해를 수첩에 저장할 때 사용자의 확인을 받는 방법

### 바이럴 결과물의 기준

- 사용자 기록에 근거해야 한다.
- 사용자를 평가하거나 진단하지 않아야 한다.
- 맥락을 모르는 사람이 봐도 민감정보가 드러나지 않아야 한다.
- “이번 주의 나를 알아봐 줬다”는 감정을 주어야 한다.
- 공유하지 않아도 개인 소장 가치가 있어야 한다.

### 시간축별 결과물 경계

현재 분석 제안은 같은 내용을 매번 다시 생성하기보다 시간축마다 역할을 나누는
것이다.

| 시간축 | 주된 역할 | 후보 결과 |
| --- | --- | --- |
| 일상 | 질문에 답하고 경험의 의미를 포착하기 | 궁금증 답변, 날짜가 있는 돌탑 순간, 관찰 |
| 주간 | 반복된 맥락과 작은 노력을 빠르게 알아보기 | 인사이트, 상장, 돌멩이의 편지 |
| 월간 | 머릿돌→일상 돌→마침돌로 한 달의 방향과 마무리 연결 | 대표 순간, 월간 회고, 마침돌 |
| 장기 | 자기이해가 어떻게 유지·변화했는지 보기 | 수첩의 변화 이력 |

각 결과물은 원본을 복사하지 않고 참조한다. 일상 원본→주간 해석→사용자 확인형
수첩이라는 큰 흐름은 결정됐으며, 월간 결과의 독자적 역할과 장기 변화 이력
명세는 아직 결정하지 않았다.

## 10. 정보구조와 각 공간의 역할

### 채택한 상위 구조 방향

`결정` 현재 채택한 탭의 명칭과 순서는 다음과 같다.

```text
돌탑 · 털어놓기 · 관찰하기 · 알아가기 · 더보기
```

`돌탑`은 기존 핵심 경험과 페블링의 고유 오브젝트를 유지한다. `털어놓기`,
`관찰하기`, `알아가기`는 사용자가 이곳에서 할 행동을 드러낸다. 특히
`알아가기`는 고정된 자기규정보다 질문·리포트·수첩을 통해 계속 나를 알아가는
과정에 초점을 둔다. `마음`은 털어놓기·관찰·질문·쉼을 모두 포괄해 행동 목적이
불명확하므로 상위 탭 이름으로 사용하지 않는다.

이 명칭과 순서는 현재 제품 방향이며 구현 완료를 뜻하지 않는다. 아이콘,
접근성 라벨, 좁은 화면에서의 표시와 첫 유료 출시 포함 범위는 화면 명세와
개발 일정에서 추가 확인한다.

### 역할 경계

| 공간 | 사용자의 주된 목적 | 포함하는 것 | 포함하지 않는 것 | 상태 |
| --- | --- | --- | --- | --- |
| 돌탑 | 가치가 드러난 삶의 순간을 알아차리고 쌓기 | 가치를 실천한 행동, 감사·다행·기쁨처럼 가치를 발견한 순간, 월별 다짐 | 모든 일기, 모든 감정 원본, 확정된 자기설명 | `결정` |
| 털어놓기 | 지금 떠오르는 감정과 생각을 부담 없이 꺼내기 | 채팅, 빠른 감정 표시, 대화 맥락의 질문, 돌멩이의 속마음 | 장기 자기프로필, 질문 라이브러리 전체 | `결정` |
| 관찰하기 | 불편한 경험과 거리를 두고 구조적으로 살펴보기 | 상황·감정·생각·행동, 불편함 관찰, 나에게 한마디 | 좋은 경험 전체, 안정된 자기프로필 | `결정` |
| 알아가기 | 질문으로 탐색하고, 리포트로 연결하고, 사용자가 확인한 내용을 수첩에 보관·갱신하기 | 돌멩이의 궁금증, 주간 리포트, 확인된 자기이해 수첩 | 모든 원본 기록의 복사본 | `결정` |
| 더보기 | 계정·설정·정책·결제 관리 | 알림, 구독, 개인정보, 계정 | 핵심 반복 경험 | `방향` |
| 쉼 | 필요할 때 즉시 편안해지기 | 아끼는 문장 재노출, 호흡, 바디스캔, 궤도 | 장기 자기분석 | `후속 후보`; 맥락형 진입부터 검토 |

### `알아가기`의 세 기능

```text
알아가기
├─ 돌멩이의 궁금증: 자주 답하며 나를 발견하는 입력
├─ 주간 리포트: 분석 대상으로 허용된 기간 기록을 연결하는 해석
└─ 수첩: 사용자가 확인한 자기이해를 장기 보관·갱신
```

세 기능은 포함 관계가 아니라 같은 목적 아래 있는 동등한 기능이다. 질문은
수첩 깊숙한 곳에 숨기지 않고 `알아가기`의 반복 진입점으로 둔다. 주간 리포트도
돌탑에 귀속하지 않는다.

> 돌탑은 가치가 드러난 삶의 순간을 쌓고, 알아가기는 질문으로 탐색하고
> 리포트로 연결하며 수첩으로 확정한다.

여기서 `확정`은 AI가 사용자를 불변의 문장으로 판정한다는 뜻이 아니다. 사용자가
현재 자신에게 맞다고 확인해 보관한다는 뜻이며, 이후 `여전히 맞음`, `달라짐`,
`과거의 나`로 갱신할 수 있다.

화면의 콘텐츠 우선순위는 사용 시점에 따라 달라질 수 있다.

- 평소: 오늘 또는 최근의 `돌멩이의 궁금증`을 먼저 노출
- 월요일 리포트 도착 후: 새 주간 리포트 진입을 먼저 노출
- 그 아래: 최근 확인한 자기이해와 질문 답변 이력

이 구조는 질문의 **일상 빈도**, 리포트의 **주간 빈도**, 수첩의 **장기 축적**을
한 공간 안에서 연결한다.

### 돌멩이의 궁금증

돌멩이의 궁금증은 한 번 완료하는 설문이 아니라, 사용자가 다른 시기에 다시
답하며 변화를 볼 수 있는 자기탐색 입력이다.

- 일상 발견: 최근 마음이 편안해졌던 순간
- 가치 탐색: 쉽지 않아도 포기하고 싶지 않은 것
- 취향·자기이해: 시간 가는 줄 모르고 했던 일
- 시간차 재질문: 과거 답변이 지금도 같은지 확인

질문 답변에는 날짜와 원문을 보존한다. 답변이 곧바로 수첩의 자기이해가 되지는
않는다. 여러 답변이나 다른 기록을 연결해 자기이해 후보를 만들고, 사용자가
확인한 경우에만 수첩으로 보낸다.

털어놓기 안의 질문은 현재 대화를 이어가기 위한 **대화 맥락 질문**이고,
돌멩이의 궁금증은 장기적으로 사용자를 알아가기 위한 **독립 반복 질문**이다.
채팅에서 궁금증으로 진입시킬 수는 있지만, 답변 원본은 질문 이력에 한 번만
저장한다.

가치탐색 질문의 원본 기능은 `알아가기`에 둔다. 돌탑에서는 작성 부담을
늘리지 않도록 그중 짧은 질문만 선택적 힌트로 재노출할 수 있다.

### 수첩의 정의

기존 `나의 발견 노트` 화면은 `아끼는 문장`, `좋아하는 순간`, `불편했던 순간`의
원본 아카이브 성격이 강했다. 현재 채택한 수첩은 원본을 모으는 곳이 아니라,
“나는 이런 것을 좋아한다”, “나는 이런 상황을 힘들어한다”처럼 사용자가 맞다고
확인한 **자기이해**를 모으는 곳이다.

- 직접 작성: 사용자가 스스로 알게 된 점을 바로 기록
- AI 제안: 관련 원본 근거를 보여주고 사용자가 확인·수정한 뒤 저장
- 리포트 연결: 주간 인사이트가 맞다면 `수첩에 저장`
- 원본 연결: 수첩 문장에는 근거가 된 기록의 참조만 유지하고 원문을 복제하지 않음
- 변화 처리: `여전히 맞음`, `달라짐`, `과거의 나` 같은 상태와 이력을 검토

좋아하는 것·힘들어하는 것·도움이 되는 것·가치·회복법·반복 특성 등이
수첩의 후보 범주다. 정확한 범주와 사용자 화면 명칭은 아직 확정하지 않았다.

### 돌탑의 정의

`결정` 돌탑은 단순한 성취 기록이나 모든 긍정 일기가 아니다.

> 내가 중요하게 여기는 것을 실천했거나, 삶에서 발견한 순간을 선택해
> 하나의 돌로 쌓는 곳

따라서 두 종류의 기록을 모두 포함한다.

1. **가치를 실천한 행동**
   - 시도했다, 애썼다, 배웠다, 잘 쉬었다, 나를 돌봤다, 누군가를 도왔다.
2. **가치를 알아차린 순간**
   - 감사했다, 다행이었다, 기뻤다, 좋았던 것을 발견했다.

기쁨의 탑·감사의 탑을 각각 만들지 않고 하나의 돌탑 안에서 의미를 구분한다.
현재 11개 `행동 태그`는 감사·다행처럼 행동이 아닌 항목까지 포괄할 수 있는지
검토한다. 사용자 표현을 `이 순간에는 어떤 의미가 있었나요?`와 같은
**의미 태그**로 넓히고 `감사했다`, `다행이었다`를 추가하는 안은 후보이다.
기존 11개를 그대로 유지할지, 이름만 바꿀지, 일부를 통폐합하거나 별도 분류로
나눌지는 아직 결정하지 않았다.

의미 태그와 개인의 가치는 같은 정보가 아니다.

- 의미 태그: 여러 사용자가 빠르게 고를 수 있는 공통 관점
  예: 시도했다, 배웠다, 감사했다, 다행이었다
- 개인의 가치: 사람마다 다르게 중요하게 여기는 삶의 방향
  예: 가족, 성장, 용기, 건강, 자유, 안정

개인 가치 연결은 선택 사항으로 두거나, 기록이 쌓인 뒤 AI가 근거와 함께
제안하고 사용자가 확인하는 방식을 검토한다. 모든 돌 작성마다 가치 선택을
강제하지 않는다.

채팅의 긍정 이모지는 현재 상태를 빠르게 포착하는 것이고, 돌탑은 다시 남겨두고
싶은 순간을 선택해 축적하는 것이다. 채팅 원본을 자동 복제하지 않고 사용자가
`돌로 남기기`를 선택하는 연결을 후보로 둔다.

불편했던 사건 자체를 돌탑에 복제하지 않는다. 다만 그 사건에서 사용자가
`버팀`, `경계 세움`, `알아차림`처럼 중요하게 여기는 행동을 발견했다면,
그 의미를 새로운 돌로 남길 수 있다.

### 돌탑과 수첩의 경계

| 기준 | 돌탑 | 수첩 |
| --- | --- | --- |
| 기본 단위 | 날짜가 있는 한 순간·행동 | 사용자가 확인한 나에 대한 문장 |
| 핵심 질문 | 오늘 무엇을 중요하게 여기며 살았거나 발견했나 | 이 경험들이 나에 대해 무엇을 알려주는가 |
| 예시 | “엄마에게 먼저 전화했다” | “나는 가까운 사람을 챙길 때 나답다고 느낀다” |
| 시간성 | 그때의 사건과 맥락을 보존 | 현재도 맞는지 갱신하고 변화 이력을 보존 |
| 가치의 역할 | 가치가 드러난 구체적 증거 | 여러 증거에서 확인한 가치·특성·회복법 |
| AI 역할 | 의미·가치 후보를 선택적으로 제안 | 근거가 있는 자기이해 후보를 제안하되 자동 확정 금지 |

같은 정보는 두 곳에 복사하지 않는다. 돌탑의 원본을 참조해 수첩 문장을 만들고,
수첩에서 확인한 가치는 이후 돌탑의 질문 힌트와 리포트 해석에 활용할 수 있다.

### 전체 자기이해 순환

```text
털어놓기·날짜가 있는 돌탑 순간·관찰·궁금증 답변
→ 날짜와 원문이 보존된 원본 기록
→ 주간 리포트가 반복 맥락과 가치 후보를 연결
→ 사용자 확인·수정
→ 수첩의 자기이해
→ 다음 궁금증·작은 실천·돌탑의 선택적 질문
```

### 오늘의 기록 통합 보기

기록 유형과 탭이 늘어나도 하루의 경험이 여러 섬으로 파편화되지 않아야 한다.
첨부안의 `최근 기록`처럼 채팅·이모지·돌탑·관찰을 시간순으로 함께 볼 필요가
있는지, 어느 수준까지 통합할지를 결정해야 한다. 이 통합 보기는 원본을 한곳에
복사하는 것이 아니라 서로 다른 원본을 하나의 타임라인에서 조회하는 방식이다.

## 11. 쉼·명상·외부 콘텐츠에 대한 현재 방향

### 기본 쉼

- 호흡하기와 바디스캔은 “명상을 잘해야 한다”는 부담보다 즉시 쉬는 경험으로
  표현한다.
- 해달의 배 움직임과 숨소리처럼 귀여움과 편안함을 결합한 안내가 후보이다.
- 기본 호흡 경험은 무료로 먼저 공개해 사용 반응을 확인하는 방향을 검토한다.
- 시간, 배경음악, 종류, 동반자 등 고급 커스터마이징은 후속 유료 가치가 될 수 있다.
- 쉼은 기본적으로 글을 쓰거나 답해야 하는 요구가 없는 공간을 우선 검토한다.
  생각이 떠올랐을 때의 기록 진입은 사용자가 원할 때만 주변부에 두는 후보가
  즉시 안정이라는 목적과 더 잘 맞는다.

### 외부 콘텐츠 수집

- 감명받은 문장·글·콘텐츠를 흘려보내지 않고 자신의 가치관과 마음관리에
  연결하는 기능을 검토한다.
- 원문을 무제한 복제하기보다 출처, 짧은 인용 또는 링크, 나에게 와닿은 이유를
  보존하는 방향이 적절하다.
- 수집한 문장 원본은 `문장·마음자원 컬렉션` 같은 한 곳에서만 관리하는 구조를
  후보로 둔다. 수첩에는 그 문장에서 발견해 사용자가 확인한 가치·취향·회복법만
  연결하고, 궤도·쉼·채팅에서는 원본을 복제하지 않고 필요할 때 재노출한다.
- 하나의 문장에 날짜별로 생각이나 자기대화를 계속 덧붙이는 스레드도 후보로
  보존한다.
- 무료 실험은 추가 니즈를 발견할 수 있지만, 8월 구독 검증 범위를 늦추지 않는
  크기로 제한해야 한다.

첨부된 `나의 발견 노트` 화면의 직접 Figma Node ID는 아직 이 문서에서 확인하지
못했다. 장기 원본으로 사용하려면 해당 노드를 찾아 원본 지도에 추가해야 한다.

## 13. 무료·유료 경계 원칙

현재 상품을 판단할 때 다음 원칙을 사용한다.

1. 감정을 기록하고 기본적으로 마음을 돌보는 기능을 인위적으로 불편하게 만들지 않는다.
2. 무료 사용자는 제품의 핵심 루프를 경험할 수 있어야 한다.
3. 유료 가치는 `더 많이 입력하기`만이 아니라, 축적된 기록의 개인화된 해석,
   연결, 재발견과 소장 가능한 결과에서 만든다.
4. AI처럼 반복 비용이 발생하는 기능은 사용량 차등이 가능하다.
5. 잠금·접근성·기본 화면 품질은 구독 장벽으로 쓰기 전에 기본 제공 필요성을
   먼저 검토한다.
6. 기존 3,900원 구매자의 평생 권한은 새 구독자의 권한 모델과 일관되게 구현한다.
7. 무료 체험은 전환 수치뿐 아니라 체험 종료 후 권한과 과거 결과물 접근까지
   설계한 뒤 제공한다.
8. 구독 기간에 생성·저장된 사용자 콘텐츠는 해지 후에도 열람할 수 있게 한다.

### 아직 확정되지 않은 권한

- 주간 리포트가 유료 전용인지, 무료 미리보기나 제한판을 제공할지
- 나에게 쓰는 시간차 편지의 무료·유료 범위
- 사진 20장 중 무료 한도
- 과거 날짜 기록의 무료·유료 경계
- 해지 후 계속 열람할 대상에 리포트·편지·AI 결과 중 무엇이 포함되는지와,
  수정·재생성·내보내기 권한
- 연간 상품만 7일 무료 체험을 제공할지
- 3개월 상품을 추가할지

## 15. 기능 채택 기준

새 기능이나 상위 탭을 검토할 때 각 항목을 `0~2점`으로 평가한다.

| 기준 | 확인 질문 |
| --- | --- |
| 단기 목표 기여 | 8월 구독 수요 검증이나 D7 리텐션에 직접 기여하는가 |
| 반복 가치 | 사용자가 한 번이 아니라 매주 다시 사용할 이유가 있는가 |
| 개인화 축적 | 기록이 쌓일수록 가치가 커지는가 |
| 문제의 명확성 | 어떤 사용자 문제를 해결하는지 한 문장으로 설명 가능한가 |
| 핵심 루프 연결 | 포착→의미→재발견 흐름 중 분명한 역할이 있는가 |
| 무료·유료 설명력 | 무료 경험을 훼손하지 않고 결제 이유를 설명할 수 있는가 |
| 구현·운영 가능성 | 현재 팀과 일정으로 만들고 안정적으로 운영할 수 있는가 |
| 안전·신뢰 | 개인정보·정서적 안전·AI 오해 위험을 통제할 수 있는가 |
| 측정 가능성 | 출시 후 성공·실패 신호를 수집할 수 있는가 |

탭 승격 점수는 아래 여섯 개 **탭 전용 기준만** 사용한다.

- 독립적인 사용자 목적이 있는가
- 매주 반복해서 진입할 가능성이 있는가
- 두 개 이상의 핵심 흐름을 담는가
- 빠른 접근이 필요한가
- 6개월 뒤에도 유지될 안정적인 개념인가
- 다른 탭과 차이를 한 문장으로 설명할 수 있는가

각 항목을 `0~2점`, 총 12점으로 평가한다. `8~12점`이면 독립 탭 후보,
`5~7점`이면 기존 탭의 핵심 모듈, `0~4점`이면 맥락형 진입을 우선 검토한다.
이 점수는 자동 결정이 아니라 비교 과정에서 누락을 줄이는 기준이다.

## 21. 갱신 규칙

1. 상세 코드·Figma 화면·설문 응답·약관 문구를 복사하지 않고 요약과 원본 링크를
   남긴다.
2. 모든 `현재` 사실에는 확인 날짜, 앱 버전 또는 커밋 중 하나를 붙인다.
3. AI의 추천은 김세인이 명시적으로 채택하기 전까지 `가설` 또는 `후보`다.
4. 결정이 바뀌면 기존 항목을 삭제하지 않고 새 결정이 어떤 결정을 대체했는지
   남긴다.
5. 질문이 해결되면 삭제하지 않고 연결된 결정 ID 또는 사실 근거를 남긴다.
6. 구현 태스크의 세부 체크리스트는 별도 기획 문서에 두고, 여기에는 제품 방향을
   바꾸는 의존성만 둔다.
7. 다음 사건이 생기면 갱신한다.
   - 제품 결정이 확정됨
   - 개발·배포 상태가 바뀜
   - 가격·상품·정책이 바뀜
   - 가설 검증 결과가 나옴
8. 활성 기획 기간에는 주 1회 전체를 검토한다.
9. 사용자 원문·개인정보·비밀키·실제 환경변수는 이 문서에 넣지 않는다.
10. `최근 변경`은 최대 5개만 유지하고 상세 이력은 Git에 맡긴다.

### 이 문서에 정보를 추가하는 기준

- 앞으로 다른 제품 결정을 할 때 다시 필요한가
- `사실·결정·방향·가설·후보·질문` 중 하나로 분류되는가
- 이를 뒷받침하는 원본이나 김세인의 명시적인 결정이 있는가
