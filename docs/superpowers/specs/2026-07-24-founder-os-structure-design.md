# Founder OS 저장소 구조 설계

작성일: 2026-07-24
최종 수정일: 2026-07-25

## 1. 목적

`founder_os_mongloo`를 창업자가 혼자 운영하는 비공개 업무 허브로 사용한다.
회의, 브랜딩·마케팅, 앱 기획·운영, 정부지원사업, 경영지원 업무의 맥락과
변경 이력을 한곳에서 관리한다.

이 저장소는 모든 원본 파일을 복제하는 보관소가 아니다. Git에 적합한 텍스트
자료와 외부 원본의 위치를 관리하고, 계속 갱신되는 표·협업 문서·대용량 파일은
각 전문 도구를 원본으로 유지한다.

## 2. 운영 원칙

### Git에 저장하는 자료

- Markdown 기반 회의록, 기획안, 체크리스트, 회고
- 업무 결정과 그 결정의 이유
- 반복해서 사용하는 템플릿
- Google Sheets, Google Docs, Drive, Notion, Figma, 앱 저장소의 위치와 용도
- 민감 원본의 내용이 아닌 존재 여부, 보관 위치, 처리 기한과 처리 상태

### 외부 도구를 원본으로 유지하는 자료

- Google Sheets: 계속 갱신되는 목록, 상태, 수치 데이터
- Google Docs·Notion: 팀에 전달하거나 함께 편집하는 완성 문서
- Google Drive: PDF, 이미지, 계약서, 세금계산서, 증빙 원본
- Figma: 디자인 원본
- 별도 앱 저장소: 실제 앱 소스코드

외부 자료는 로컬 파일로 정기 복제하지 않는다. 저장소에는 원본 링크, 용도,
관련 업무 영역, 최신 데이터 확인 규칙을 기록한다.

### 민감정보

다음 항목은 비공개 Git 저장소에도 넣지 않는다.

- 비밀번호, API 키, 인증서와 인증 토큰
- 주민등록번호, 계좌정보와 불필요한 개인정보
- 세금계산서, 계약서, 증빙의 원본 파일
- 실제 환경변수가 들어 있는 `.env` 파일

Git은 파일을 삭제해도 과거 커밋에 내용이 남을 수 있으므로, 민감 원본은
접근 권한이 제한된 Drive 등에서 관리한다.

## 3. 폴더 구조

최상위 폴더는 정렬과 탐색이 쉽도록 숫자 접두사가 붙은 영어 이름을 사용한다.
실제 문서 제목과 내용은 한국어로 작성할 수 있다.

│   └── README.md

│   ├── backlog.md

│       ├── meta/
│       └── google/

### 영역별 역할

- `00_inbox`: 위치가 아직 정해지지 않은 메모와 아이디어의 임시 수집함
- `01_dashboard`: 현재 할 일, 백로그, 반복 업무
- `10_meetings`: 연도별 회의록과 결정사항
- `20_brand_marketing`: 브랜드 전략, 온드미디어, 유료 광고 기획과 회고
- `30_app`: 앱 아이디에이션, 기획, 디자인 의견, 운영, 리뷰, QA, 웹 공지와 약관 기획
- `40_grants`: 지원사업 후보, 공통 템플릿, 지원사업별 진행 자료
- `50_business_admin`: 증빙·세무·재무 업무의 메모, 처리 상태와 원본 위치
- `80_resources`: 모든 외부 원본과 별도 앱 저장소의 색인
- `90_templates`: 반복 업무에 사용하는 문서 양식
- `99_archive`: 완료됐거나 더 이상 활성 상태가 아닌 자료

빈 폴더는 Git이 추적하지 않으므로 각 주요 영역에는 역할을 설명하는
`README.md` 또는 초기 템플릿을 둔다.

하나의 자료가 여러 업무 영역에 걸치더라도 원본 문서는 가장 관련성이 높은
한 곳에만 둔다. 다른 영역에서는 링크로 참조해 중복 문서와 서로 다른 최신본이
생기지 않게 한다. 위치를 바로 판단하기 어려운 새 자료는 `00_inbox`에 넣고
정기적으로 알맞은 영역으로 옮긴다.

## 4. 외부 원본 연결

`80_resources/external-sources.md`에는 다음 정보를 표 형식으로 관리한다.

- 자료 이름
- 자료 유형
- 원본 링크
- 관련 업무 영역
- 사용 목적
- 최신 데이터 확인 시점
- 민감도

예를 들어 정부지원사업 관련 요청을 처리할 때는 저장된 스냅샷보다 등록된
Google Sheets의 최신 데이터를 먼저 조회한다. 로컬 CSV나 XLSX 내보내기 파일은
명시적인 보관 목적이 없는 한 저장소에 넣지 않는다.

`AGENTS.md`에는 관련 업무를 시작할 때 외부 원본을 먼저 확인하고, 최신 조회가
불가능한 경우 그 사실을 명시하도록 작업 규칙을 기록한다.

외부 연결이 끊겼거나 권한이 없을 때는 오래된 로컬 자료를 최신 자료처럼
사용하지 않는다. 사용자에게 연결 또는 접근 권한이 필요하다고 알린다.

### Figma 아이디에이션 아카이브

정리되지 않은 Figma 아이디에이션 화면은 완료 자료로 취급해 `99_archive`로
보내지 않고, 재활용 가능한 제품 아이디어 라이브러리인 `30_app/ideation`에서
관리한다.

- Figma에는 화면 디자인 원본을 유지한다.
- `30_app/ideation/catalog.md`에는 아이디어 이름, Figma 노드 직접 링크,
  수집일, 관련 영역, 상태와 태그를 기록한다.
- 분석과 맥락이 많이 필요한 아이디어는 `30_app/ideation/ideas`에 별도
  Markdown 문서로 작성한다.
- 실제 기획에 채택된 아이디어는 이동하거나 복제하지 않고
  `30_app/planning`의 기획 문서에서 링크로 참조한다.

아이디어 상태는 `검토 전`, `보류`, `기획 반영`, `폐기` 네 가지로 관리한다.
`폐기` 상태도 당시 판단 근거와 학습을 재사용할 수 있도록 기록을 유지한다.
각 아이디어 문서에는 해결하려던 문제, 핵심 아이디어, 활용 가능한 요소,
적용하지 않은 이유와 관련 태그를 기록한다.

## 5. Git 운영 방식

### 브랜치

문서 중심의 개인 저장소이므로 일상적인 변경은 `main`에 직접 커밋한다.

다음 경우에만 별도 브랜치를 사용한다.

- 전체 폴더 구조를 크게 개편할 때
- 여러 영역을 동시에 바꾸는 대규모 수정
- 기존 자료를 손상할 가능성이 있는 실험
- 앞으로 팀원이 GitHub에서 직접 공동 작업하게 되는 경우

### 커밋 시점

나중에 독립적으로 이해하거나 되돌릴 수 있는 의미 단위가 완성됐을 때
커밋한다.

- 회의록 한 건과 결정사항 정리를 완료했을 때
- 앱 기능 하나의 기획안을 작성하거나 변경했을 때
- 지원사업 하나의 등록과 체크리스트 작성을 완료했을 때
- 마케팅 캠페인 계획이나 회고를 완료했을 때
- 외부 데이터 원본을 등록하거나 변경했을 때
- 템플릿이나 저장소 운영 규칙을 변경했을 때

서로 무관한 회의록, 앱 기획, 지원사업, 마케팅 변경을 하나의 커밋으로
묶지 않는다. 반대로 문장 하나를 작성할 때마다 커밋할 필요는 없다.

### 커밋 메시지

`영역: 변경 내용` 형식을 기본으로 사용한다.

```text
meeting: 앱 기획회의 결정사항 정리
app: 온보딩 개선안 초안 추가
qa: 7월 출시 QA 결과 기록
marketing: 유튜브 콘텐츠 계획 추가
grants: 예창패 제출 체크리스트 갱신
template: 회의록 템플릿 추가
chore: Python용 gitignore 설정
```

커밋 전에는 `git status`로 변경 파일을 확인하고, 가능하면 `git add .` 대신
해당 변경에 속한 파일을 명시적으로 추가한다.

일반적인 작업 순서는 다음과 같다.

```bash
git pull
git status
git add 수정한-파일
git commit -m "영역: 변경 내용"
git push
```

## 6. `.gitignore`

Python 소스와 프로젝트 설정은 추적하되 가상환경, 캐시, 빌드 결과와 실제
환경변수 파일은 제외한다. macOS가 자동 생성하는 `.DS_Store`도 제외한다.

```gitignore
.venv/
venv/
__pycache__/
*.py[cod]
.pytest_cache/
.mypy_cache/
.ruff_cache/
build/
dist/
*.egg-info/
.env
.env.*
!.env.example
.DS_Store
```

`*.py`, `requirements.txt`, `pyproject.toml`, `.env.example`은 Git으로
관리한다.

## 7. 초기 구축 범위

승인 후 초기 구축에서 다음 작업을 수행한다.

1. 위 폴더 구조와 각 영역의 짧은 안내 파일 생성
2. `README.md`를 저장소 사용 안내로 확장
3. 외부 원본 색인과 앱 저장소 색인 생성
4. Figma 아이디에이션 카탈로그와 아이디어 문서 템플릿 생성
5. 기본 회의록, 기획서, QA, 지원사업 템플릿 생성
6. `AGENTS.md`에 외부 원본 확인과 민감정보 처리 규칙 기록
7. Python과 macOS용 `.gitignore` 생성
8. 생성 결과를 검증하고 하나의 초기 구조 커밋으로 저장

## 8. 완료 기준

- 처음 보는 사람도 `README.md`만으로 각 자료의 저장 위치를 판단할 수 있다.
- 모든 업무 문서는 하나의 명확한 영역에 배치할 수 있다.
- Google Sheets 등 외부 원본을 로컬에 복제하지 않고 최신 자료를 확인할 수 있다.
- Figma 화면 원본을 복제하지 않고 아이디어를 검색하고 재활용할 수 있다.
- 민감 원본과 비밀정보가 Git에 포함되지 않는다.
- 일상적인 커밋과 브랜치 사용 기준이 문서로 명확하게 남아 있다.
