# 털어놓기 온보딩 상세기획 정의 계획

> 이 계획은 구현 계획이 아니라, 개발자가 해석 없이 구현할 수 있는 화면·상태·정책
> 명세를 만드는 작업 순서다. 각 단계는 체크박스로 진행 상태를 관리한다.

**목표:** 모든 사용자가 같은 최초 설정 흐름으로 털어놓기 첫 기록까지 도달하며,
속마음을 채팅 답변으로 오해하지 않는 온보딩 상세 명세를 완성한다.

**기준 문서:**
[`30_app/planning/venting-onboarding-context.md`](../../../30_app/planning/venting-onboarding-context.md)

**산출물 원칙:** Figma를 사람이 읽고 전달하는 화면·정책 원본으로 사용한다.
Markdown은 AI가 작업 맥락과 결정 근거를 잃지 않기 위한 보조 원본이다. 최종 정책은
중복 없이 소제목으로 묶어 Figma에 기재하고, 개발자는 Figma를 기준으로 확인한다.

## 전역 제약

- 털어놓기와 속마음은 함께 최초 출시하며 사용자군별 온보딩 분기를 만들지 않는다.
- 유효한 서버 프로필은 설정 완료 상태로 취급하고 중복 저장으로 덮어쓰지 않는다.
- 호칭은 필수지만 실명 입력을 요구하지 않는다.
- 속마음은 답변·답장·응답으로 표현하지 않는다.
- 속마음 체험과 피드백은 온보딩 필수 범위에 넣지 않는다.
- 완료 화면의 생각은 AI가 아닌 규칙 기반 고정 문구다.
- AI 동의를 거부해도 털어놓기 기록 저장·조회는 가능해야 한다.
- `developer-handoff/` 수정은 대상과 범위를 제시하고 별도 승인을 받은 후 진행한다.

---

### 1단계: 최신 원본과 구현 기준선 고정

**목적:** 오래된 Figma 화면이나 예상 코드에 기반한 상세 기획을 막는다.

**입력:** 최신 Figma 온보딩 섹션, `pebbling-expo/`, 본 맥락 문서

**산출물:** 화면·코드·정책 원본 목록과 확인일

- [x] 최신 Figma Node URL을 다시 받아 전체 상위 화면과 상태 화면을 목록화한다.
- [x] Figma 화면별 Node ID와 임시 화면명을 지정한다.
- [x] `pebbling-expo/`에서 현재 설정값, 호칭, 온보딩 완료 상태와 코치마크 상태의
  저장 위치를 읽기 전용으로 확인한다.
- [x] 프로필 조회 상태와 설정 완료 후 재진입을 실제 스키마 기준으로 분류한다.
- [x] 기획과 구현이 다른 항목만 차이 목록으로 남긴다.

**완료 기준:** 화면·데이터·코드의 최신 원본 위치와 차이가 한 표에 정리돼 있다.

**완료 기록 (2026-08-09):** 최신 원본은 Figma `841:61618`, 현재 앱 기준선은
루트의 `pebbling-expo/`다. 화면별 정의와 차이 목록은 Figma 및 기준 문서의
`1단계 기준선 결과`에 반영했다. 호칭 문자 범위, 완료 화면 복귀, 머리장식 개수,
첫 코치마크 trigger와 피드백 노출 정책은 검토 후 확정했다. 머리장식 에셋도
완성됐으며 Figma component suffix인 `default`, `sprout`, `upset`, `cone`,
`bald`, `weed`를 내부 key로 사용한다.

### 2단계: 설정 완료 여부와 진입 조건 정의

**목적:** 사용자군을 나누지 않고 서버 프로필 조회 상태별 시작 화면을 확정한다.

**산출물:** 프로필 조회 상태별 진입 결정표

- [x] 조회 중, 유효한 프로필, 프로필 없음, 조회 실패·유효하지 않은 상태를 구분한다.
- [x] 프로필 상태별 최초 화면과 건너뛸 단계를 지정한다.
- [x] 완료 전 영구 로컬 임시 저장을 만들지 않는 범위를 확정한다.
- [x] 온보딩 완료를 판정하는 최소 서버 필드를 확정한다.

**완료 기준:** 각 프로필 상태가 정확히 하나의 진입 경로를 갖고, 설정 완료
프로필을 중복 저장으로 덮어쓰는 경로가 없다.

**완료 기록 (2026-08-09):** 상세 결과는
[`30_app/planning/venting-onboarding-state-and-recovery.md`](../../../30_app/planning/venting-onboarding-state-and-recovery.md)에
작성했다. 유효한 프로필, 프로필 없음, 조회 중, 조회 실패·유효하지 않은 프로필을
구분하고 설정 완료 프로필을 중복 저장으로 덮어쓰지 않도록 확정했다.

### 3단계: 전체 상태 전이와 저장 시점 정의

**목적:** 정상 흐름과 중단·실패 복구를 같은 상태 모델로 설명한다.

**산출물:** 상태 전이표와 단계별 저장 계약

- [x] `미시작 → 외형 선택 → 호칭 입력 → 저장 중 → 완료 → 첫 기록` 상태를
  정의한다.
- [x] 각 화면에서 `다음`, `뒤로`, `닫기`, 앱 종료, 재진입 시 이동할 상태를 정한다.
- [x] 외형·호칭은 현재 화면에서 유지하고 마지막 완료에서만 서버에 저장하도록 정한다.
- [x] 저장 실패·오프라인·중복 탭과 앱 종료 뒤 행동을 정한다.
- [x] iOS 스와이프와 Android 시스템 뒤로가기를 같은 상태표에 포함한다.

**완료 기준:** 어느 단계에서 앱이 종료돼도 재진입 화면과 보존 데이터가 명확하다.

**완료 기록 (2026-08-09):** 완료 전 영구 로컬 draft, `이어서 설정하기`, 오프라인
동기화와 timeout 전용 상태를 제외했다. 완료 전 앱 종료 시 처음부터 다시 설정하고,
저장 실패 시 현재 화면의 값을 유지해 재시도한다. 완료 여부는 서버 프로필로 판정한다.

### 4단계: 화면별 UI 계약 정의

**목적:** 각 화면이 보여주고 받으며 다음 화면으로 넘기는 값을 확정한다.

**산출물:** 화면별 UI 명세표

- [x] 소개, 외형 설정, 호칭 설정, 저장 중, 완료, 숲 첫 진입 화면을 확정한다.
- [x] 각 화면의 제목, 설명, CTA, 보조 행동과 노출 조건을 기록한다.
- [x] 버튼의 기본·비활성·로딩·오류 상태를 정의한다.
- [x] 설정 완료 화면에 생각구름과 `숲에서 이야기하기` CTA를 반영한다.
- [x] 화면별 진입 조건과 다음 화면으로 넘기는 값을 명시한다.

**완료 기록 (2026-08-09):** Figma의 화면별 정의와 공통 정책을 현행화했다.
프로필 조회 4상태, 세션 내 값 유지, 완료 전 앱 종료, 최종 1회 저장, 저장 실패와
설정 완료 후 재진입을 공통 패널에 정리하고 화면별 패널에는 해당 화면의 행동만
남겼다.

**완료 기준:** 개발자가 Figma 위치만 보고도 상태와 버튼 행동을 추측할 필요가 없다.

### 5단계: 외형 선택과 호칭 입력 규칙 확정

**목적:** 에셋과 입력 예외 때문에 구현·QA가 다시 열리지 않게 한다.

**산출물:** 설정 옵션표, 입력 검증표, 오류 문구

- [x] 실제 색상·눈·머리 장식의 옵션 ID와 표시명을 확정한다.
- [x] 눈의 기본값과 머리장식 첫 번째 기본 이미지 값을 명시한다. 사용자에게
  `없음` 텍스트 라벨은 노출하지 않는다.
- [ ] 카드 너비, 간격, 3개 전체와 다음 카드 일부 노출, 스크롤 스냅을 수치화한다.
- [x] 장식별 중간·큰 에셋을 Figma에 반영한다.
- [x] 호칭 길이, 공백, 허용 문자, 이모지와 오류 문구를 확정한다.
- [ ] 받침 판별이 가능한 문장과 조사 없는 대체 문장을 함께 작성한다.

**완료 기준:** 허용·거부 입력 예시와 모든 옵션 ID가 QA 가능한 표로 존재한다.

### 6단계: 첫 기록 코치마크와 Info 정의

**목적:** 필요한 설명만 행동 직전에 제공하고 반복 방해를 막는다.

**산출물:** 코치마크 노출표와 Info 정보 구조

- [ ] 입력창 첫 탭 안내와 첫 메시지 전송 후 `답하지 않음` 안내 문구를 확정한다.
- [ ] VentHome 최초 진입의 Chat → Peek 연속 dim 코치마크 앵커, 닫기 방식과
  계정별 1회 노출 키를 정한다.
- [ ] 코치마크를 닫지 않고 앱을 종료한 경우의 재노출 여부를 정한다.
- [ ] Info의 설명 순서와 설정 변경·AI 데이터 안내 연결을 정의한다.
- [ ] 코치마크와 Info가 같은 개념에 서로 다른 표현을 쓰지 않는지 검수한다.

**완료 기준:** 모든 안내가 `언제, 누구에게, 몇 번, 어떻게 닫히는지`로 정의된다.

### 7단계: 속마음 진입과 첫 설명 상태 정의

**목적:** 속마음을 강조하지 않으면서 비활성·실패 상태를 무반응으로 남기지 않는다.

**산출물:** 속마음 버튼 상태표와 첫 설명 명세

- [ ] 생성 조건 미충족, 가능, 생성 중, 완료, 횟수 소진, 네트워크 오류, 생성 실패,
  AI 동의 없음 상태를 정의한다.
- [ ] 상태별 버튼 스타일, 탭 행동과 안내 문구를 작성한다.
- [ ] 생성 조건과 일일 횟수 초기화 기준의 제품 계약 원본을 연결한다.
- [ ] 첫 생성 성공 후 설명 화면의 형식·문구·닫기·재진입 규칙을 확정한다.
- [ ] 생성 실패와 안전 도움 결과에서 첫 설명을 노출할지 구분한다.

**완료 기준:** 버튼의 모든 상태와 첫 설명의 정확한 노출 조건이 테스트 가능하다.

### 8단계: 설정 변경과 과거 결과 정책 정의

**목적:** 온보딩 이후 사용자가 외형과 호칭을 바꿀 때 기존 데이터의 의미를 보존한다.

**산출물:** 설정 변경 흐름과 과거 데이터 표시 규칙

- [ ] Info 또는 설정에서 내 돌멩이 설정으로 이동하는 경로를 확정한다.
- [ ] 외형과 호칭 변경 시 저장·취소·실패 행동을 정의한다.
- [ ] 기존 기록과 속마음 결과를 유지한다는 정책을 명시한다.
- [ ] 과거 AI 결과의 호칭은 생성 당시 문장으로 보존한다.
- [ ] 설정 변경 중 앱 종료와 다른 기기 동시 변경 충돌 처리를 정의한다.

**완료 기준:** 설정 변경이 기존 기록이나 결과를 소급 수정하지 않는다.

### 9단계: 동의·데이터·측정 명세 정의

**목적:** AI 처리 동의와 제품 분석을 사용자 원문 없이 운영 가능하게 한다.

**산출물:** 저장 필드 목록, 동의 흐름, 분석 이벤트 명세

- [ ] 설정값, 단계 완료, 코치마크 확인과 첫 설명 확인 필드를 구분한다.
- [ ] 속마음 첫 생성 전에 AI 분석 동의를 확인하는 화면과 거부 상태를 정의한다.
- [ ] 동의 철회 후 털어놓기 기록과 속마음 버튼의 상태를 정한다.
- [ ] 설정 시작·완료·중단, 첫 기록, 첫 생성 시도·성공·실패 이벤트를 명명한다.
- [ ] 이벤트 속성에서 호칭·원문·PII가 제외됐는지 검수한다.

**완료 기준:** 데이터별 저장 목적·위치·보유 범위와 이벤트 속성이 명확하다.

### 10단계: 플랫폼·접근성·예외 UI 검수

**목적:** 대표 iPhone 화면만 맞고 실제 기기에서 깨지는 문제를 출시 전에 찾는다.

**산출물:** 플랫폼·접근성 상태별 QA 체크리스트

- [ ] 작은·큰 iOS 화면과 주요 Android 화면 폭을 선정한다.
- [ ] 키보드·긴 호칭·영문·이모지·큰 글자 크기를 검수한다.
- [ ] VoiceOver·TalkBack 라벨과 포커스 순서를 정한다.
- [ ] 선택 상태가 색상만으로 전달되지 않는지 확인한다.
- [ ] 애니메이션 감소 설정의 정적 표현을 확인한다.
- [ ] 느린 네트워크, 오프라인, 저장 실패와 앱 강제 종료 시나리오를 검수한다.

**완료 기준:** 주요 화면 크기, 보조기술과 실패 상태별 기대 결과가 모두 있다.

### 11단계: Figma·기획·QA 최종 정합성 검수

**목적:** 서로 다른 원본이 충돌한 채 개발자에게 전달되는 일을 막는다.

**산출물:** 최종 커버리지 표와 승인 대기 목록

- [ ] 프로필 상태와 상태 전이의 모든 상태가 Figma 또는 명시적 비화면 처리에
  연결되는지 확인한다.
- [ ] Figma 문구, 기획 용어와 코드 필드 이름의 대응표를 만든다.
- [ ] HOLD 기능이 화면과 개발 범위에 남아 있지 않은지 확인한다.
- [ ] 정상·중단·실패·설정 완료 후 재진입 QA 케이스의 누락을 검사한다.
- [ ] 김세인이 최종 승인해야 할 문구와 정책만 별도 목록으로 추린다.

**완료 기준:** 누락 화면과 미정 분기가 0개이거나, 명시적인 승인 대기 항목으로
분리돼 있다.

### 12단계: 개발자 인계 계획 수립

**목적:** 승인된 기획만 현재 구현과의 변경요청으로 변환한다.

**주의:** 이 단계에서 `developer-handoff/`를 수정하기 전에 대상 파일과 변경 범위를
김세인에게 제시하고 별도 승인을 받는다.

- [ ] 현재 코드 대비 변경·유지·제외 항목을 나눈다.
- [ ] 개발자에게 필요한 데이터 계약, 상태표, 화면 링크와 QA 기준만 추린다.
- [ ] Prompt Lab과 속마음 생성 로직처럼 온보딩과 직접 관련 없는 변경은 분리한다.
- [ ] 예상 수정 파일은 실제 코드 확인 뒤 적고 추측 경로를 사용하지 않는다.
- [ ] 인계 파일 변경 범위에 대한 사용자 승인을 요청한다.

**완료 기준:** 개발자가 이번 온보딩 범위만 독립적으로 구현·검증할 수 있는 인계
범위가 확정돼 있다.
